# llm — DeepSeek CLI 에이전트

터미널에서 DeepSeek API를 사용해 파일 읽기/편집, 검색, 셸 실행을 수행하는
경량 코딩 에이전트입니다. Python 표준 라이브러리만으로 동작하며, 별도의
패키지 설치가 필요 없습니다.

**버전:** v0.14.0 — 로컬 프롬프트 관리·간결한 CLI·세션 메뉴

## 최소 사용법

```bash
llm                    # REPL 대화형 실행
llm "프로젝트 분석해줘"  # 1회 실행 후 종료
llm bal                # API 잔액 조회
llm session            # 로컬 세션 관리 메뉴
llm help               # 간결한 도움말
```

REPL에서는 `/agent`, `/chat`, `/plan`으로 모드를 전환하며, `/undo`로 마지막 추적 파일 편집을 복원합니다. `/bal`은 잔액, `/prompt`는 프롬프트 관리, `/help`는 도움말, `/exit`는 종료입니다. **`llm "질문"`은 TTY 여부와 관계없이 1회만 실행합니다.**

### 프롬프트 관리

REPL에서 `/prompt`를 입력하면 세 종류의 프롬프트를 선택해 조회·편집·삭제할 수 있습니다. 텍스트 편집기는 `EDITOR` 환경변수를 우선 사용하고 없으면 `nano` 또는 `vi`를 사용합니다. 다음 요청부터 반영되며 기존 대화 기록은 유지합니다.

| 프롬프트 | 파일 | 적용 범위 |
|---|---|---|
| System | `~/.local/share/llm/system.md` | 현재 PC 전체 |
| Project | `<작업폴더>/.llm/rules.md` | 해당 프로젝트(공개 가능한 규칙만) |
| Session | `<LLM_HISTORY_DIR>/prompts/<세션>.md` | 해당 세션만 |

`LLM_HISTORY_DIR`이 비어 있으면 Session 프롬프트는 `<작업폴더>/.llm/prompts/`에 저장됩니다. 전역·세션 프롬프트와 대화 기록은 GitHub에 업로드하지 않습니다. 프로젝트 규칙 파일은 코드와 함께 Git에서 관리될 수 있으므로 비밀정보를 넣지 마세요.

### 로컬 세션 관리

`llm session`은 대화형 메뉴를 표시합니다. 목록·대화 조회·현재 폴더에서 세션 선택·초기화·삭제를 제공합니다. 다른 작업 폴더에 연결된 세션은 여기서 수정하거나 빼앗을 수 없습니다. 초기화와 삭제에는 세션 이름 재입력 확인이 필요합니다.

### 실행 화면

```text
✦ DeepSeek CLI  v0.14.0
  Project  AX
  Session  AX
  Mode     AGENT
  History  /data/llm-sessions (local only)

  /plan 계획 · /chat 대화 · /prompt 지침 · /help 도움말

agent ❯
```

## v0.14 변경 사항

### REPL 비용·맥락·권한 기본 정책

- **맥락 절약**: 오래된 도구 출력부터 정리한 뒤 필요할 때만 대화를 요약합니다. 최근 메시지와 tool call 구조는 보존합니다.
- **재요약 억제**: 요약 직후에는 새 메시지가 충분히 쌓일 때까지 다시 요약하지 않습니다. 단, 사용량이 한도를 크게 초과하고 실제 줄일 오래된 내용이 충분하면 예외적으로 요약합니다.
- **권한 설정 최소화**: REPL은 안전한 읽기와 작업 폴더 내 허용 작업을 자동 처리하며, 설치·권한 상승·위험한 작업은 확인합니다. `sudo` 등은 자동 승인 대상이 아닙니다.
- **비용 확인**: `/bal` 또는 `llm bal`로 잔액을 확인하고, `/cost`(호환 명령)에서 현재 프로세스의 API 사용량을 확인할 수 있습니다. 불필요한 요약 API 호출을 줄이지만 비용 감소 수치는 실제 사용량으로 검증해야 합니다.


- 입력 인자가 없을 때만 REPL을 시작하고 `llm "질문"`은 단발성 실행으로 변경했습니다.
- 외부 명령어는 `llm`, `llm "질문"`, `llm bal`, `llm help`, `llm session` 중심으로 정리했습니다. 이전 별칭은 호환성 차원에서 남겨 두되 기본 도움말에 표시하지 않습니다.
- REPL에서 `/prompt`로 System·Project·Session 지침을 로컬에서 관리하며, `/agent`, `/chat`, `/plan`, `/undo`, `/bal`을 사용할 수 있습니다.
- 세션 관리 메뉴를 통합하고 시작 화면에서 원격 Git 동기화 상태를 제거했습니다.
- `LLM_HISTORY_DIR`로 로컬 기록 경로를 지정하며 `.llm/prompts/`를 Git 추적에서 제외합니다.
- 이전 명령어 설명이 남아 있는 하위 절은 구버전의 기록입니다. 실제 CLI는 이 절과 `llm help`를 기준으로 사용하세요.

| 모드 | 에이전트/채팅 | + **plan 모드**(읽기 전용 조사 → 계획만) |
| REPL | `input()` 한 줄, `/exit /sync /chat /agent` | readline(방향키·히스토리·Tab 완성), 여러 줄(`\` 이어쓰기, `"""` 블록), `/help /clear /compact /model /cost /undo /plan /rules /bg` |
| 맥락 | `.llm/rules.md`만, 문자 수 기준 압축 | `@파일` 첨부, `CLAUDE.md`/`AGENTS.md`(상위 폴더·`~/.claude`) 반영, **실제 토큰 수** 기준 압축, 오래된 긴 도구 결과 일괄 비우기 |
| 도구 | 5개, 순차 실행, 셸 최대 180초 | + `web_fetch`, `task`(읽기 전용 서브에이전트), 백그라운드 셸, grep `context`/`output`, 읽기 전용 호출 **병렬 실행**, 셸 최대 600초 |
| 구조 | `agent.py` 단일 파일, 테스트 9개 | `llmlib/` 9개 모듈로 분리(셸 정책·보안·재시도·맥락·웹·백그라운드 셸), 테스트 61개(셸 정책 표 테스트 포함) |

## 설치

### 1. API 키 설정

`agent.py`와 `llm` 래퍼는 시작 시 아래 순서로 `.env`를 자동으로 읽습니다
(**앞이 우선**, 이미 설정된 환경변수는 덮어쓰지 않음).

1. `LLM_ENV_FILE`로 지정한 경로
2. **저장소 폴더의 `.env`** — `llm`/`agent.py`가 있는 폴더 (권장)
3. `/etc/env/.env` — 시스템 공용(예전 방식)

가장 간단한 방법은 저장소 폴더에 `.env`를 만드는 것입니다.

```bash
cd ~/codespace/llm   # 또는 ~/codespace/workbayNext/llm (WSL에서 WN 옆 클론)
printf 'DEEPSEEK_API_KEY=sk-...\n' > .env
chmod 600 .env
```

```dotenv
# .env 형식
DEEPSEEK_API_KEY=sk-...
```

> `.gitignore`에 `.env`가 들어 있어 **커밋·push 되지 않습니다**(키 유출 방지).
> 저장소를 복사해도 `.env`는 따라가지 않으므로 새 PC에서는 한 번 다시
> 만들어야 합니다.

`.env` 파일이 없으면 일반 환경변수로 지정해도 됩니다.

```bash
export DEEPSEEK_API_KEY=sk-...
```

### 2. 실행 파일 배치

`llm`(bash 래퍼)과 `agent.py`가 같은 폴더에 있어야 합니다.
`llm` 래퍼는 자기 위치를 기준으로 `agent.py`를 찾습니다.
심볼릭 링크로 걸어 두어도 링크를 따라가 실제 폴더를 찾습니다
(`readlink -f` 없이 동작, macOS/BSD 포함). 실행할 Python 실행기는
`LLM_PYTHON`(기본 `python3`)으로 바꿀 수 있습니다.

```bash
# 저장소 위치 (환경에 따라 다름)
~/codespace/llm/
# 또는
~/codespace/workbayNext/llm/
├── llm          # 실행 진입점 (bash)
└── agent.py     # 실제 로직 (python)
```

### 3. 전역 명령으로 등록 (권장)

`~/bin`은 사용자 전역 명령을 두는 관례적인 경로입니다. 여기에 심볼릭 링크를
걸고 PATH에 등록하면 어디서든 `llm`으로 실행할 수 있습니다.

```bash
mkdir -p ~/bin
ln -sf ~/codespace/llm/llm ~/bin/llm   # 실제 클론 경로로
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

동작 확인:

```bash
which llm          # → /home/<user>/bin/llm
readlink ~/bin/llm # → /home/<user>/codespace/userscript/llm/llm
llm                # 인자 없이 실행하면 대화형(REPL) 시작 (비TTY는 1턴)
```

> `~/bin`이 PATH에 없으면 새 셸에서 `llm`을 찾지 못합니다. 위 `export PATH`
> 한 줄이 영구 등록의 핵심입니다.

## 다른 PC에서 시작하기

새 PC에서는 **① 코드 가져오기 → ② API 키 넣기 → ③ PATH 등록 → ④ 확인** 순서로
하면 끝입니다. 아래 명령을 위에서부터 그대로 복사해 붙여넣으세요
(`<user>`는 새 PC의 사용자 이름).

### ① 코드 가져오기

GitHub(비공개)에 있으므로 clone 하면 됩니다.

```bash
mkdir -p ~/codespace
git clone git@github.com:hanurijang/llm.git ~/codespace/llm
chmod +x ~/codespace/llm/llm
```

> - `Permission denied (publickey)`가 나오면 새 PC의 SSH 공개키가 GitHub에
>   없는 것입니다: `ssh-keygen -t ed25519` → `~/.ssh/id_ed25519.pub` 내용을
>   GitHub **Settings → SSH keys**에 등록.
> - **이 저장소의 remote는 계정 별칭을 쓸 수 있습니다**(예:
>   `git@github-hanurijang:hanurijang/llm.git`). 별칭은 이 PC의 `~/.ssh/config`
>   에만 있는 개인 설정이라 새 PC에는 따라가지 않습니다. clone이
>   `Could not resolve hostname github-hanurijang`로 실패하면 ① `~/.ssh/config`
>   에 같은 `Host` 항목을 넣거나 ② `git@github.com:hanurijang/llm.git`로
>   clone 하세요(기본 키를 쓸 때). 현재 remote는 `git remote -v`로 확인합니다.
> - clone은 실행 권한까지 그대로 가져오므로 위 `chmod +x`는 보험입니다.
>   clone이 아니라 USB·rsync로 폴더를 복사했다면 그 한 줄이 꼭 필요합니다.

### ② API 키 넣기

```bash
cd ~/codespace/llm
printf 'DEEPSEEK_API_KEY=sk-여기에-본인-키\n' > .env
chmod 600 .env
```

> sudo 없이 됩니다. `.env`는 `.gitignore`에 있어 커밋되지 않습니다.
> 저장소 폴더의 `.env`(권장)나 `/etc/env/.env`, `~/.bashrc` export 어느
> 쪽이든 인식합니다(앞이 우선).

### ③ 전역 명령 등록

```bash
mkdir -p ~/bin
ln -sf ~/codespace/llm/llm ~/bin/llm
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

### ④ 확인 (위에서부터 차례로)

```bash
which llm               # → /home/<user>/bin/llm
llm session ls          # 상태 + 버전(v0.13.0) 표시 (API 호출 없음)
llm balance             # 키·네트워크 확인
llm ask "안녕"          # 1턴으로 모델 응답 확인
llm "이 폴더 요약해줘"   # 대화형 시작 + 도구까지 확인
```

### macOS·다른 환경에서 쓸 때

Linux/WSL이 아니어도 아래 두 가지만 맞추면 됩니다.

| 상황 | 증상 | 해결 |
|------|------|------|
| `~/bin` 심볼릭 링크 | `python3: can't open file '…/agent.py'` | v0.11.1부터 **`readlink -f` 없이** 링크를 해석합니다. 그래도 실패하면 링크가 실제 저장소를 가리키는지 확인: `readlink ~/bin/llm` → 저장소 경로. `ln -sf ~/codespace/llm/llm ~/bin/llm`로 다시 연결 |
| 기본 `python3` 가 3.9 (macOS 구형) | 실행 즉시 `SyntaxError`(타입 문법) 또는 버전 오류 | `LLM_PYTHON=python3.12 llm …` 처럼 3.10+ 실행기 지정 (Homebrew: `brew install python@3.12`). 영구 설정은 `~/.zshrc`에 `export LLM_PYTHON=python3.12` |
| 셸 설정 파일 이름 | `llm` 이 새 터미널에서 안 잡힘 | macOS 기본 셸은 zsh — `~/.bashrc` 대신 **`~/.zshrc`** 에 `export PATH="$HOME/bin:$PATH"` |
| `git`/`ssh` 인증 | clone·`llm sync` 실패 | SSH 별칭은 PC 로컬 설정입니다(위 ① 참고). 키를 등록하거나 `git@github.com:…` 주소 사용 |

`llm` 래퍼는 심볼릭 링크를 **여러 단계 따라가고**(링크→링크→파일), 상대 경로
링크도 해석합니다. `LLM_PYTHON` 을 바꾼 뒤 `llm --help` 가 사용법을 출력하면
정상이고, 실행기를 못 찾거나 버전이 낮으면 그 사실을 알려 주는 오류가 나옵니다.

### 새 PC에서의 코드 설치와 세션

- GitHub의 Clone은 **소스코드와 규칙**만 가져옵니다. 개인 대화 기록은 GitHub에 없으며 새 PC로 자동 이전되지 않습니다.
- 각 PC의 세션은 해당 PC 로컬에만 저장됩니다. 이 프로젝트는 다른 PC와 대화를 공유하거나 동기화하지 않습니다.
- `~/.local/share/llm/`에는 로컬 세션 매핑과 설정이 저장됩니다. `.llm/rules.md`는 코드와 함께 가져옵니다.
- 이미 사용 중인 PC라면 기존 `.llm/` 기록을 백업한 뒤 코드 업데이트를 진행하세요.

### 준비물 체크

| 항목 | 확인 명령 | 없을 때 |
|------|-----------|---------|
| Python 3.10+ | `python3 -V` | 최신 버전 설치 (3.9 이하면 문법 오류). macOS에서 여러 버전이면 `LLM_PYTHON=python3.12 llm …` |
| bash | `bash --version` | Linux/macOS/WSL은 기본 포함 |
| `readlink` | `readlink ~/bin/llm` | 없어도 `~/bin` 대신 저장소의 `llm` 을 직접 실행하면 동작 (v0.11.1부터 `-f` 불필요) |
| git (선택) | `git --version` | clone·`mv` 이어받기 안내에만 사용 |

## 빠른 시작

```bash
# 이 폴더에서 에이전트에게 질문 (도구 자동 사용)
llm "이 프로젝트 구조를 요약해줘"

# 파일 내용을 읽고 고치도록 요청
llm "agent.py의 확인 프롬프트 문구를 더 친절하게 다듬어줘"

# 한 번만 묻고 바로 끝내기(대화형으로 들어가지 않음)

# 도구 없이 순수 채팅
llm chat "파이썬에서 리스트와 튜플의 차이는?"

# 셸 명령 확인 생략 (자동화/신뢰 환경)
llm --yes "테스트 돌리고 실패하면 원인 요약해줘"

# 기본값: 작업 폴더 안 명령은 확인 없이(safe). 밖·설치 등은 확인
llm "테스트 돌리고 실패하면 원인 요약해줘"

# 더 관대하게: sudo·설치·폴더 밖 삭제만 확인
llm --trust "빌드 정리하고 린트·포맷까지 돌려줘"

# 모델의 사고 과정 원문까지 보고 싶을 때 (기본은 도구 진행만 표시)
llm --show-thinking "이 코드의 버그 원인을 추적해줘"

# 읽기 전용 명령도 매번 확인 (자동 실행 비활성)
llm --confirm-all "이 폴더 상태를 점검해줘"

# 다른 세션(예: 설계 노트)의 맥락을 주입해 이어서 작업
llm --ref design-notes "이 맥락 참고해서 인증 모듈 리팩터링 이어줘"

# 이 세션에서 자동 허용한 셸 명령 목록 보기 / 비우기
llm shell allow
llm shell allow clear

# 확인 프롬프트에서 허용해 자동 실행된 셸 명령 기록 보기 / 비우기
llm shell log        # 최근 20건 (llm shell log 50 처럼 개수 지정)
llm shell log clear
```

세션은 실행한 폴더에 자동으로 연결됩니다. 같은 폴더에서 다시 `llm`을
호출하면(인자 없이 실행하면 대화형) 이전 대화 맥락이 이어집니다.

## 사용법 (CLI 옵션)

### 기본 실행

| 명령 | 설명 |
|------|------|
| `llm` | **대화형(REPL) 시작**(터미널일 때). 파이프·리다이렉션은 1턴 |
| `llm "질문"` | 터미널이면 대화형으로 시작해 **첫 턴** 실행, 아니면 1턴 |
| `llm ask "질문"` | **1턴만** 실행하고 종료(대화형으로 가지 않음) |
| `llm chat "질문"` | 도구 없이 순수 채팅 (터미널에서도 1턴) |
| `llm plan "질문"` | 읽기 전용 계획만 (터미널에서도 1턴) |
| `llm session ls` | 상태·세션 목록 보기 (API 호출 없음) |

> `llm chat`/`llm plan`은 터미널에서도 대화형으로 들어가지 않고 1턴만 실행합니다.
> 여러 턴을 이어가려면 대화형에서 `/plan`, `/chat`을 쓰세요.

### 서브커맨드

첫 번째 인자가 아래 이름이면 해당 동작으로 펼쳐집니다(`llm_ask`/`llm chat` 처럼
붙여 쓰지 말고 **띄어** 씁니다). 그림 뒤의 옵션을 직접 줘도 같은 동작입니다.

| 명령 | 동작 | 같은 옵션 |
|------|------|----------|
| `llm ask "질문"` | 1턴 실행 | `--once` |
| `llm chat "질문"` | 도구 없이 채팅 | `--chat` |
| `llm plan "질문"` | 읽기 전용 계획만 | `--plan` |
| `llm repl` · `agent` · `i` | 대화형 시작 | `-i` / `--interactive` |
| `llm sync` | 비활성화 — 대화 기록은 로컬 전용 | `--sync-history` |
| `llm undo` | 직전 턴 편집 되돌리기 | `--undo` |
| `llm balance` | 잔액 조회 | `--balance` |
| `llm rules [show\|init]` | 규칙 보기·생성 | `--rules` / `--init-rules` |
| `llm shell log [N\|clear]` | 셸 허용/실행 로그 | `--shell-log` / `--shell-log-clear` |
| `llm shell allow [clear]` | 셸 자동 허용 목록 | `--allow-list` / `--allow-clear` |
| `llm session ls` | 세션 목록 | `--list-sessions` |
| `llm session adopt` | 이 폴더에 기록 세션 연결 | `--session-adopt` |
| `llm session view [이름]` | 대화 내용 보기(읽기 전용) | `--view` |
| `llm session clear` | 현재 세션 내용 비우기 | `--clear` |
| `llm session delete [이름]` | 세션 파일 삭제·매핑 해제 | `--delete` |
| `llm session compact [이름]` | 지금 요약·백업 | `--summarize` |
| `llm session run [이름]` | 직전 응답의 스크립트 실행 | `--run` |
| `session ref <이름>` | 다른 세션 맥락 주입 | `--ref` |

> 서브커맨드는 **첫 번째 인자**일 때만 인식됩니다. 예: `llm undo -s mysession` (O),
> `llm -s mysession undo` (X, 질문으로 처리).
> 예전 플래그(`--allow-list`·`--shell-log`·`--view` …)는 계속 동작하지만
> `--help` 에서는 숨겨져 있습니다(2단계에서 제거 예정).

### 옵션

| 옵션 | 설명 |
|------|------|
| `-s, --session <이름>` | 이 폴더를 지정한 세션에 매핑 (이 폴더의 기존 매핑은 갈아탐, 남의 세션은 거부) |
| `--once` | 1턴만 실행하고 종료 (`llm ask "질문"`) |
| `-i, --interactive` | 대화형(REPL) 시작 — 인자 없이 실행하는 것과 같음 (`llm repl` · `llm agent`) |
| `--ref <이름>` | 다른 세션의 맥락을 이번 세션에 1회 주입 (여러 번 지정 가능, 참조 대상은 읽기 전용) |
| `--list-sessions` | 세션 목록 보기 (`llm session ls`, API 호출 없음) |
| `--chat` | 도구 없이 순수 채팅 모드 |
| `-y, --yes` | 셸·편집·웹 요청 확인 생략 (위험 패턴만 차단, 비밀 노출 명령 확인도 생략되므로 주의) |
| `--safe` | 작업 폴더 안 명령 자동(**기본과 동일**) |
| `--trust` | sudo·설치·폴더 밖 삭제만 확인(관대) |
| `--model <이름>` | 모델 지정 (기본: `deepseek-flash`) |
| `--max-steps <N>` | 에이전트 루프 최대 반복 (기본: 100). 한도에 도달하면 종료하지 않고 **이어서 N회 더 진행할지 `[y/N]`으로 확인** |
| `--no-stream` | 스트리밍 비활성화 |
| `--no-balance` | 시작 잔액 조회 및 종료 시 잔액·소요 비용·토큰 사용량 표시 생략 (`/cost` 금액도 이유 안내로 대체) |
| `--no-rates` | 실시간 환율 조회를 끄고 가정 환율로 환산 (`LLM_RATES=0`과 동일) |
| `--no-thinking` | 사고(thinking) 비활성화 (더 빠른 응답, `--chat`에서 유용) |
| `--show-thinking` | 사고 과정 원문을 회색으로 실시간 출력 (기본은 글자 수만 표시) |
| `--confirm-all` | 읽기 전용 명령도 확인 후 실행 (모든 셸 명령 + 파일 편집 확인, 다른 모드·환경변수보다 우선) |
| `--confirm-edits` | 파일 편집마다 diff 를 보여주고 `[y/N/a]` 확인 (`LLM_CONFIRM_EDITS=1`과 동일, `a`=이번 실행 동안 생략) |
| `--plan` | plan 모드: 편집·쓰기 셸을 막고 읽기 전용 조사 후 구현 계획만 제시 (`llm plan "질문"`) |
| `--undo` | 직전 턴에 `edit` 도구로 바꾼 파일을 원래대로 (`llm undo`, `-y`로 확인 생략). 셸로 바꾼 파일은 대상 아님 |
| `--allow-list` | 이 세션의 셸 자동 허용 목록 보기 (`llm shell allow`) |
| `--allow-clear` | 이 세션의 셸 자동 허용 목록 비우기 (`llm shell allow clear`) |
| `--shell-log [N]` | 이 세션의 셸 허용/실행 로그 보기 (최근 N건, 기본 20). `llm shell log` |
| `--shell-log-clear` | 이 세션의 셸 로그 비우기. `llm shell log clear` |
| `--init-rules` | 이 폴더에 `.llm/rules.md` 생성 (`llm rules init`) |
| `--rules` | 이 폴더의 세션 규칙 보기 (`llm rules show`) |
| `--summarize` | 현재 대화를 지금 요약·백업(강제 실행). `llm session compact` |
| `--sync-history` | 로컬 기록 보호를 위해 비활성화됨 |
| `--no-pull` | 호환성 옵션(대화 자동 Pull은 항상 비활성화됨) |
| `--run` | 직전 응답의 bash/sh 코드 블록 추출 후 실행 (`llm session run`) |
| `--view` | 세션 대화 내용 보기 (Markdown). `llm session view [이름]` |
| `--clear` | 현재 세션 내용만 비우기 (`llm session clear`) |
| `--delete` | 현재 세션 파일 삭제 및 폴더 매핑 해제 (`llm session delete [이름]`) |
| `--balance` | DeepSeek API 잔액 조회 (화폐별 잔액 + 원화 환산). `llm balance` |

> 여기서 `--allow-all`/`--auto-workspace`/`--session-adopt` 같은 옛 플래그와
> 위 괄호 안의 옛 표기도 **별칭으로 계속 동작**합니다(도움말에서는 숨김).

셸 실행 범위 우선순위: `--confirm-all` > `--trust` > `--safe` >
`LLM_SHELL_TRUST`/`LLM_ALLOW_ALL` > `LLM_AUTO_WORKSPACE` > **기본(safe)**. **직접 준 CLI 옵션이
환경변수를 이깁니다.** 시작 헤더의 `셸` 행에 `확인=safe|trust|…`가, `설정` 행에
`rules`·`sync`가, `이어가기` 행에 로컬 턴·미커밋·원격 상태가 표시됩니다.

```text

────────────── ✦ llm v0.13.0 · 대화형 ──────────────
  세션      llm
  폴더      ~/codespace/userscript/llm
  셸        확인=safe(폴더 안)
  설정      rules on · sync off
  이어가기  로컬 12턴 · 원격과 같음
  완화      --safe / --trust / --yes (셸 확인 완화) · sudo 등 권한 상승은 목적 설명 후 매번 확인
  로그      ~/.local/share/llm/shell_log_llm.jsonl (기록 켬 · 조회 /log)
  도움말    /help 명령 · 빈 줄·/exit 종료 · @파일 첨부 · 줄 끝 \ 이어쓰기 · 1턴만 llm ask "질문"

```

### 사용 예

```bash
# 세션 이름을 명시적으로 고정 (이 폴더에 바인딩, 기존 매핑은 갈아탐)
llm -s mysession "이 대화는 mysession으로 저장해줘"

# 다른 폴더 세션의 대화 내용 보기 (읽기 전용)
llm session view other        # 예전: llm -s other --view

# 다른 세션(예: 설계 노트)의 맥락을 주입해 이어서 작업
llm --ref design-notes "이 맥락 참고해서 이어줘"

# 최근 답변의 스크립트를 추출해 실행
llm session run

# 세션 초기화 / 삭제
llm session clear
llm session delete

# 파일을 첨부해 질문 (@경로: 파일 내용, 폴더면 목록)
llm "@agent.py 의 cmd_agent 흐름 설명해줘"

# 먼저 계획만 받고, 확인 뒤 실행
llm plan "로그인 기능 추가 방법"
llm "좋아, 그 계획대로 진행해"

# 직전 턴의 편집 되돌리기
llm undo
```

> 서브커맨드(`ask`/`chat`/`plan`/`sync`/`undo`/`balance`/`rules`/`shell`/`session`/`repl`)는
> **첫 번째 인자**일 때만 인식됩니다. 예: `llm undo -s mysession` (O),
> `llm -s mysession undo` (X, 질문으로 처리)

### 대화형 모드(REPL) 명령

`llm`(인자 없음) 또는 `llm -i` · `llm repl` · `llm agent`에서 쓰는 명령입니다.
`/`까지 치고 Tab 을 누르면 완성됩니다.

| 명령 | 설명 |
|---|---|
| `/help` | 명령 목록 |
| `/clear` | 대화 비우기 (이전 대화는 `summaries/<세션>/cleared-*.json`에 백업) |
| `/compact` | 지금 대화 요약(압축) |
| `/model [이름]` | 모델 보기/바꾸기 |
| `/cost` | 이번 REPL 세션의 누적 토큰 사용량 + **소요 금액**(세션 시작 잔액 − 현재 잔액, 원화 환산) |
| `/balance` | 현재 DeepSeek 잔액(화폐별 + 원화 환산 + 적용 환율), `llm balance` 와 동일. 조회값은 `/cost` 캐시와 공유 |
| `/undo` | 직전 턴의 파일 편집 되돌리기 |
| `/plan` | plan 모드 켜기/끄기 (프롬프트가 `llm:plan>`로 바뀜) |
| `/rules` | 세션 규칙·프로젝트 지침(CLAUDE.md 등) 보기 |
| `/bg` | 백그라운드 셸 작업 목록 |
| `/log [N]` | 셸 허용/실행 로그 보기 (`/log clear` 로 비우기, `llm shell log` 와 동일) |
| `/sync` · `/chat` · `/agent` · `/exit` | 기록 올리기 · 채팅 모드 · 에이전트 모드 · 종료 |

진입 화면(시작 헤더)은 제목 줄과 행으로 나뉘어 있습니다:

```text

────────────── ✦ llm v0.13.0 · 대화형 ──────────────
  세션      llm
  폴더      ~/codespace/userscript/llm
  셸        확인=읽기 전용 자동 (repl 기본)
  설정      rules on · sync off
  이어가기  로컬 12턴 · 원격과 같음
  완화      --safe / --trust / --yes (셸 확인 완화) · sudo 등 권한 상승은 목적 설명 후 매번 확인
  로그      ~/.local/share/llm/shell_log_llm.jsonl (기록 켬 · 조회 /log)
  도움말    /help 명령 · 빈 줄·/exit 종료 · @파일 첨부 · 줄 끝 \ 이어쓰기 · 1턴만 llm ask "질문"
```

1턴 실행(`llm ask`)·채팅 모드(`llm chat`)에서는 `셸`·`완화`·`로그` 행을 빼고
같은 헤더를 보여 줍니다(제목의 모드 표기가 다름).

- **Ctrl+C**: 모델 응답·도구 실행 중이면 **그 턴만 중단**하고 프롬프트로 돌아옵니다.
  입력 중에 누르면 입력만 취소, 연달아 두 번 누르면 종료합니다. `Ctrl+D`/빈 줄도 종료.
- **여러 줄 입력**: 줄 끝에 `\`를 붙이면 다음 줄로 이어지고, `"""`만 있는 줄로
  감싸면 블록 전체를 한 번에 보냅니다(붙여넣기용).
- 입력 히스토리는 `~/.local/share/llm/repl_history`에 저장되어 ↑/↓로 불러옵니다.

> 옵션과 프롬프트를 함께 쓸 때는 프롬프트를 `--`로 구분할 수 있습니다.
> 예: `llm -s mysession -- "질문"`

## 세션과 폴더 매핑

- **작업 폴더는 항상 지금 있는 폴더(`cwd`)입니다.** 경로를 지정하는
  `--root`는 없습니다.
- 하나의 **세션 이름**은 하나의 **폴더**에만 연결됩니다. 대화 기록은 기본적으로
  **작업 폴더 안 `<작업폴더>/.llm/history_<세션>.json`**에 저장됩니다(저장소와
  함께 `git push`/`pull` 되어 다른 PC에서 이어감). `LLM_HISTORY=home`으로
  실행하면 예전처럼 `~/.local/share/llm/history_<세션>.json`에 저장됩니다.
- 폴더-세션 매핑은 `~/.local/share/llm/bindings.json`에 저장되며, 경로 키는
  로드·저장 시 **정규화**됩니다(심볼릭 링크 해소, 뒤쪽 구분자 제거,
  macOS/Windows 대소문자 통일). `a`, `a/`, `a/.`, 심볼릭 링크 경로는 모두
  같은 폴더로 취급됩니다.
- 매핑이 없는 폴더에서 대화를 시작하면 **폴더 이름 기반으로 세션이 자동
  생성**됩니다. (예: `~/work/api` → 세션 `api`; 이름 충돌 시 해시 접미사 추가)
  폴더를 옮겨 온 흔적(고아 매핑)이 있으면 새 세션 대신 **이어받을지 먼저
  확인**합니다([폴더를 옮기거나 이름을 바꾼 경우](#폴더를-옮기거나-이름을-바꾼-경우-mv) 참고).

### 대화 기록 — 로컬 저장 전용

`llm/.env`에 다음과 같이 지정할 수 있습니다.

```dotenv
# 빈 값(기본): 현재 작업 폴더의 .llm/
LLM_HISTORY_DIR=

# 별도 데이터 SSD에 로컬 보관하려면 위 행 대신 사용
# LLM_HISTORY_DIR=/data/llm-sessions
```

별도 경로를 사용하는 경우에도 **세션은 작업 폴더별로 서로 다른 이름으로 관리**됩니다. 세션 파일명은 `history_<세션명>.json`, 요약은 `summaries/<세션명>/`입니다. 세션 이름이 겹치면 폴더 경로를 이용해 이름을 구분합니다. 기존 경로의 기록을 새 위치로 바꾸려면 직접 백업·이전하세요. **저장 경로는 Git 저장소 외부를 권장**합니다.


대화와 세션 요약은 현재 PC의 `<작업폴더>/.llm/`에 저장합니다. `LLM_HISTORY=home` 설정 시 `~/.local/share/llm/`에 저장합니다. GitHub에 기록을 올리는 기능은 제공하지 않습니다.

```bash
llm                         # 기존 로컬 세션 이어가기
llm session ls              # 현재 PC의 세션 목록 조회
llm session view            # 로컬 대화 기록 보기
llm session compact         # 로컬 대화 요약과 백업
```

- `llm sync`(`--sync-history`)는 보안상 비활성화되어 오류 안내 후 종료합니다.
- `LLM_AUTO_SYNC=1`과 `LLM_AUTO_PULL=1`을 지정해도 개인 대화는 Git으로 전송하거나 수신하지 않습니다.
- 홈에 있는 예전 기록은 작업 폴더의 `.llm/`으로 옮겨질 수 있습니다. 저장 위치를 바꾸기 전에 현재 PC의 기록을 백업하세요.
- Git은 **소스코드·테스트·프로젝트 규칙** 용도로만 사용합니다. 세션 파일을 수동 `git add -f`로 강제 추가하지 마세요.


### 로컬 경로 설정 빠른 확인

```bash
# 코드 저장소의 .env 수정 (비밀키를 함께 저장하므로 Git에 올리지 않음)
printf '\nLLM_HISTORY_DIR=/data/llm-sessions\n' >> /data/projects/llm/.env
mkdir -p /data/llm-sessions
chmod 700 /data/llm-sessions

# 작업 폴더마다 독립 세션 생성
cd /data/projects/프로젝트A && llm session ls
```

### 소유와 권한

| 동작 | 이 폴더의 세션 | 다른 폴더의 세션 |
|------|------|------|
| 대화·이어가기 / `session clear` / `session delete` / `session compact` / `session run` / `shell allow clear` | 가능 | **거부** |
| `-s <이름>` 으로 매핑(설정) | 가능 (기존 매핑은 갈아탐) | **거부** |
| `session view` / `shell allow` (보기) | 가능 | **가능 (읽기 전용)** |
| `--ref <이름>` (다른 세션 맥락 주입) | 가능 | **가능 (참조 대상은 읽기 전용)** |

- 다른 폴더가 소유한 세션 이름을 `-s`로 지정하면 거부하고 소유 폴더만
  안내합니다. 매핑 파일은 바뀌지 않습니다.
- 같은 폴더에서 `-s <다른 이름>`을 다시 지정하면 **이 폴더의 매핑이 그 세션으로
  갈아타고**, 이전 세션은 매핑만 풀립니다(기록은 유지). 별도의 해제 명령은 없습니다.
- 대화 내용을 보고 싶은 등 **참조**가 필요할 때는 `llm session view`처럼 보기만 하는
  명령만 허용됩니다. 아직 주인이 없는 이름을 지정하지 않은 이상, 보고만 하는
  명령은 (고아 매핑에서 이어받기를 고른 경우를 빼고) 바인딩을 만들지 않습니다.
- 남의 세션을 이 폴더로 **끌어오는 명령은 두지 않습니다**(소유권 보호).
- `llm session delete`는 이 폴더 세션의 파일 삭제와 폴더 매핑 해제를 함께 합니다.

### 폴더를 옮기거나 이름을 바꾼 경우 (`mv`)

- 폴더를 `mv`/`rm` 하면 예전 경로의 매핑은 **고아**가 됩니다.
- **대화를 시작하면**(`llm "질문"`, 매핑 없음) 사라진 폴더에 남은 세션 중
  **옮겨온 것으로 보이는 후보**를 보여주고 이어받을지 물어봅니다.
  번호를 고르면 그 세션으로 매핑해 이어가고, **Enter = 새 세션**입니다.
  예:
  ```text
  이 폴더는 아직 세션에 연결되어 있지 않습니다.
  사라진 폴더에 남은 세션 후보입니다 (폴더를 옮기셨나요?):
     1) mysession  ← /old/path/proj  (이름 일치)
  이어받을 번호 [1-1] / Enter=새 세션 'proj2':
  ```
- **인자 없이 `llm` 만 실행**해도(대화형 진입/`llm session ls`) 매핑이 없으면 이어받을 후보가
  있음을 알려줍니다(묻지는 않음):
  ```text
  ℹ️  사라진 폴더에 남은 세션 후보입니다 (폴더를 옮기셨나요?):
     1) mysession  ← /old/path/proj
  ℹ️  이어받으려면  llm -s <이름>  (예: mysession)
  ```
- **조회/정리 명령**(`llm session view`·`clear`·`compact`·`shell allow` 등)도 같은
  후보를 보여줍니다. TTY면 번호를 골라 **그 자리에서 이어받아**(Enter=취소)
  해당 명령을 그 세션으로 실행하고, 자동화/파이프(비TTY)면 안내만 하고
  "매핑된 세션이 없습니다"로 끝납니다.
- 이어받으면 **이후 이 폴더가 어느 세션으로 이어지는지** 안내합니다
  (`ℹ️ 이후 이 폴더는 세션 'mysession'(으)로 이어집니다 (다시 지정하려면 llm -s <이름>)`).
- 후보 판정은 폴더 **이름 유사도 + 부모 경로 일치**로 점수를 매기고, `MOVE_SIMILARITY_MIN`
  (0.3) 이상만 최대 `MOVE_CANDIDATE_LIMIT`(5)개 보여줍니다. 대화를 시작하는
  실행에서 **TTY가 아니면**(자동화/파이프) 묻지 않고 새 세션을 만듭니다.
- 물어보지 않고 바로 이어받으려면 예전처럼 `llm -s <세션>` 을 쓰면 됩니다.
  (예전 경로는 존재하지 않아도 되고, 별도 해제 명령도 필요 없습니다.)
- 이어받으면 매핑 파일의 사라진 경로 항목이 **새 경로로 정리**됩니다. 매핑을
  저장하는 시점(새 세션 자동 생성 · `-s` · 이어받기)에 사라진 폴더 항목이 함께
  정리되므로, 경로가 다시 생겨도 예전 매핑이 자동으로 돌아오지는 않습니다
  (필요하면 `-s`로 다시 연결하세요).

### 다른 세션 맥락 참조 (`--ref`)

진행 중인 세션(A)을 유지한 채 **다른 세션(B)의 맥락을 참고**하고 싶을 때 씁니다.

- `llm session ref <이름> "질문"` 은 B의 맥락을 **이번 세션(A)에 1회 주입**한 뒤 대화를
  진행합니다. A는 그대로 유지되고, B는 **읽기 전용**으로만 읽어 소유권·기록이
  바뀌지 않습니다(`llm session view`와 같은 권한 규칙).
- 주입 내용은 B의 사용자/에이전트 발화를 뽑아 `[참고: 다른 세션의 맥락]` 표시가
  붙은 **사용자 메시지로 A 기록에 저장**됩니다(이후 턴에서도 A의 맥락으로 남음).
- 여러 세션을 동시에 참조할 수 있습니다: `llm --ref A --ref B "질문"`.
- 프롬프트 없이 `llm --ref B` 로 실행하면 **주입만 하고 종료**합니다
  (A 세션이 이미 있어야 함).
- B의 발췌가 `REF_MAX_CHARS`(24,000자)를 넘으면 요약을 시도하고, 실패하면 앞부분만
  잘라 씁니다. 기록이 없는 세션 이름은 경고 후 건너뜁니다.
- **맥락 참고만 하려면 `--ref`** (소유권은 옮기지 않음).

## 대화 요약과 백업

대화가 길어지면 컨텍스트를 줄이기 위해 **자동 요약**되고, 요약 시점의
원본도 함께 백업됩니다.

- 트리거(하이브리드)는 **압축 대상**, 즉 최근 `SUMMARY_KEEP_RECENT`(24)개를
  제외한 앞부분만 보고 판단합니다. 그 앞부분이 문자 수
  `SUMMARY_TRIGGER_CHARS`(120,000) 초과 **또는** 메시지 수
  `SUMMARY_TRIGGER_MESSAGES`(160) 초과 시 자동 실행.
  - 최근 메시지는 어차피 유지되므로, 대용량 도구 출력 몇 개로 요약이 걸리지
    않습니다.
- **쿨다운**: 직전 요약 이후 새 메시지가 `SUMMARY_MIN_NEW_MESSAGES`(40)개
  미만이면 요약하지 않습니다. 요약 직후 재요약이 겹치는 것을 막습니다.
  - 쿨다운은 요약본에 남긴 "요약 시점 메시지 수" 표시(HTML 주석)로 판단하며
    화면 표시에는 영향이 없습니다.
- 요약 후 최근 `SUMMARY_KEEP_RECENT`(24)개 메시지만 남기고, 이전 내용은
  요약문으로 대체합니다.
- 요약문은 최대 `SUMMARY_MAX_CHARS`(4,000)자, 한국어로 생성됩니다.
- **작업 계획(todo)도 함께 보존**됩니다. 요약문 앞머리에
  `[진행 중인 작업 계획 — …]` 블록(목표 + 현재 항목/상태)과 기계용 스냅샷
  `<!-- llm-todo:{...} -->`을 넣어, 요약 후에도(그리고 다음 실행에서도) 계획을
  새로 시작하지 않고 **같은 작업으로 이어갑니다**. 자세한 내용은
  [작업 계획(todo) 표시](#작업-계획todo-표시) 참고.
- 수동 실행: `/summary`, `/summarize`, `/요약` 슬래시 명령 또는
  `llm session compact`(강제).
- 백업(요약본 `.md` + 원본 스냅샷 `.json`)은
  `<작업폴더>/.llm/summaries/<세션>/`(기본) 또는 `~/.local/share/llm/summaries/<세션>/`
  (`LLM_HISTORY=home`)에 저장됩니다.

## 응답 표시와 사고 과정

기본은 **진행 과정만 보여주는 출력**입니다. 화면에는 아래 내용만 남습니다.

- **도구 호출/결과 한 줄**: `🔧 shell 파일을 작성하거나 수정합니다` 처럼
  **무엇을 하려는지 의도**를 먼저 표시하고(파일 도구는 경로), 실행이 끝나면
  같은 줄 오른쪽에 `✓`/`✗`와 결과 첫 줄을 붙입니다. 명령 원문은 확인이 필요할
  때만 프롬프트에 나옵니다.
- **진행 상태 한 줄**: 모델이 응답을 만드는 동안 `🧠 사고 중… 1,234자`,
  `✍️ 작성 중… 567자`처럼 글자 수만 갱신합니다.

- **제자리 갱신(스텝 패널)**: 진행 상황은 **새 줄로 쌓이지 않습니다**. 계획이
  있으면 작업 계획 블록(목표 + 항목 + 항목별 하위 작업 로그)이, 없으면 단계
  머리말(`⚙️ N단계`)과 그 단계의 도구 줄이 한자리에서 갱신됩니다. 도구를 실행할
  때마다 다시 그리므로 화면에는 **지금까지의 계획과 진행 중인 항목의 로그만**
  남습니다(TTY 전용).
  - 요약(todo)·경고·확인 프롬프트처럼 남겨야 하는 출력이 끼어들면 패널을 잠시
    지웠다가 그 아래에 다시 그립니다(계획이 메시지 아래로 내려갑니다).
  - TTY가 아니거나 `LLM_RAW`가 설정되면 제자리 갱신을 끄고, 블록에서 **바뀐
    줄만** 새 줄로 출력해 **순서대로 내려가는 로그로 남깁니다**(파이프·자동화에서
    결과 유실 없음).
  - 계획이 화면보다 커지면 자리 갱신을 포기하고, 그때부터 바뀐 줄만 새 줄로
    찍습니다(그림이 터미널을 넘어가며 화면이 어긋나는 것을 막기 위함).
  - 최종 답변이 나오기 직전에는 계획 블록을 지우지 않고 **화면에 남깁니다**.

```text
🎯 셸 도구의 재시도 로직을 추가하고 README를 갱신한다
📋 작업 계획  (완료 1/3 · 진행 중 2/3 · ⚙️ 4단계)
────────────────────────────────────────────
   ✅ 1/3 README 현황 확인
          🔧 read_file README.md  ✓ 763 lines
   ▶ 2/3 todo 도구 문서화
          🔧 edit README.md  ✓ updated (2 replacements)
   ☐ 3/3 잔액 푸터 옵션 문서화
```

- **사고 과정(thinking)**: 모델이 `reasoning_content`를 반환해도 **원문은 기본
  으로 출력하지 않습니다**(영어 사고 과정이 화면을 채우는 것을 막기 위함).
  원문을 보고 싶으면 `--show-thinking`을 쓰면 회색으로 실시간 출력합니다.
  아예 사고를 끄려면 `--no-thinking`.
- **최종 답변**: 완료 후 **내장 Markdown 렌더러**(`llmlib/mdrender.py`, 표준
  라이브러리만)로 정리해 출력합니다. 외부 도구(glow 등) 설치가 필요 없고,
  TTY가 아니거나 `LLM_RAW` 설정 시 원문으로 출력합니다. 스트리밍 중에는 글자
  수만 표시합니다.
  - 지원: ATX/`===` 헤딩, 순서·비순서·체크 목록(긴 항목은 행잉 인덴트로 접음),
    펜스 코드블록(언어 라벨 + 좌측 세로줄, 긴 줄은 폭에 맞춰 자름), 인용,
    수평선, 파이프 표(열 정렬), 인라인 코드·굵게·기울임·취소선·링크
    (`[텍스트](url)` → 텍스트 + 회색 URL).
  - 한글·전각 문자는 표시 폭을 2로 세어 표·목록 열이 어긋나지 않습니다
    (`display_width`).
  - `NO_COLOR`면 색 없이 **구조만** 정리하고 Markdown 기호는 지웁니다
    (`--no-color`와 같은 판정). 파이프·리다이렉트에서는 원문 그대로 남겨
    로그가 왜곡되지 않게 합니다.
  - 답변 앞 줄은 `✅ 작업 완료 (N단계 · 소요 시간)`이고, 답변 본문 뒤에는
    회색 구분선을 그어 **답변 블록의 끝**을 표시합니다(다음 프롬프트와 섞이지 않게).
  - 모델에는 **답변 골격**을 지시합니다: 결론을 한두 문장으로 먼저 쓰고, 해당될
    때만 `변경한 파일`/`검증`/`남은 일` 같은 짧은 섹션을 붙입니다(빈 섹션은 생략,
    계획을 되풀이하지 않음). 폴더별로 다른 형식을 쓰려면 `.llm/rules.md`에 적습니다.
    - **마지막 줄에 git 동기화 상태 한 줄**(예: `🔁 동기화: …`)을 붙이도록
      `.llm/rules.md`에 규칙을 둘 수 있습니다. 이 줄에는 push 여부와 **push한
      커밋(짧은 해시·제목)**, 그 커밋이 바꾼 **코드/파일 목록**(대화 기록 JSON만
      바뀐 경우와 코드가 바뀐 경우를 구분)을 함께 적어, 무엇이 원격에 올라갔는지
      한눈에 보이게 합니다. 실패 시 원인도 숨기지 않고 적습니다.

```text
✅ 작업 완료 (7단계 · 1m 05s)
──────────────────────────────── 🤖 답변 ────────────────────────────────
요약
────────────

• 확인 프롬프트 오탐을 제거했습니다.

검증
────────────

• `python3 -m py_compile agent.py` 통과
─────────────────────────────────────────────────────────────────────────
```

- **비스트리밍/폴백**: `--no-stream`이거나 스트림이 실패하면 완료 후 결과를
  한 번에 출력합니다. 이때도 사고 과정 원문은 감추고 `사고 과정 N자 진행`
  안내만 보여줍니다(`--show-thinking`이면 원문 출력).
- 사고 과정은 API 프로토콜상 같은 턴에서만 유효하므로 디스크에 저장하지
  않습니다.

### 작업 계획(todo) 표시

에이전트는 작업을 시작할 때 `todo` 도구로 **목표(조치 요약)와 전체 작업 계획을
먼저 보여주고**, 진행에 따라 상태를 갱신합니다. 표시 형식은 아래와 같습니다.

```text
🎯 셸 도구의 재시도 로직을 추가하고 README를 갱신한다
📋 작업 계획  (완료 1/3 · 진행 중 2/3 · ⚙️ 4단계)
────────────────────────────────
   ✅ 1/3 README 현황 확인
   ▶ 2/3 todo 도구 문서화
   ☐ 3/3 잔액 푸터 옵션 문서화
```

- **목표/조치 요약(`goal`)**: 목록 **상단**에 표시합니다. 터미널 폭에 맞춰
  줄바꿈하고, 이어지는 줄은 `   `로 들여써 목표 줄임을 알아보기 쉽게 합니다.
  에이전트가 무엇을, 왜 하려는지 먼저 알려 줍니다. 이후 호출에서 `goal`을
  생략하면 **이전 목표가 그대로 유지**됩니다. 단 **이전 계획이 모두 완료(done)된
  뒤**이거나 계획이 없으면 옛 목표를 물려받지 않습니다(끝난 작업의 목표가 새
  작업의 목표처럼 보이지 않게).
- **항목 번호(`2/3`)**: 진행 위치가 눈에 들어오도록 항목마다 번호를 붙입니다.
  헤더의 진행률/진행 중 항목 번호(자리수 맞춤)와 함께, 계획이 **위에서 아래로
  차례로 내려가는 모습**이 보입니다.
- **항목별 하위 작업 로그**: 그 항목을 처리하는 동안 실행한 도구 줄이 항목
  **바로 아래**에 붙습니다(예: `🔧 read_file README.md  ✓ …`). 즉
  `3/8 진행 중 → 하위 로그 → 3/8 완료 → 4/8 진행 중 → 하위 로그 …` 순서로
  화면이 갱신됩니다.
  - 항목마다 최근 `TODO_LOG_SHOW`(6)줄만 보여주고 나머지는
    `… 앞선 로그 N줄 접음`으로 요약합니다(보관은 `TODO_LOG_KEEP`(40)줄).
  - 내용이 같은 항목은 계획이 갱신되어도 로그를 **그대로 이어 붙입니다**.
  - 하위 로그는 **화면 전용**이라 모델에게 보내지 않습니다(토큰 낭비 없음).
  - 계획이 화면보다 커지면 오래된 항목의 로그부터 접어
    (`… 지난 로그 N줄 접음`) 진행 중인 흐름이 계속 보이게 합니다
    (`TODO_BLOCK_MAX`(24)줄, 터미널 높이도 함께 고려).
- 마커: `✅` 완료(done) · `▶` 진행 중(in_progress) · `☐` 대기(pending)
- 이번 실행에서 처음 도구를 쓰는데 `todo`가 없으면 **딱 한 번** 계획(todo)을
  먼저 세우도록 상기시킵니다.
- **하나의 작업으로 계속 이어갑니다.** 목록이 `TODO_MAX_ITEMS`(50)개를 넘으면
  **완료된 항목부터 접어** `… 완료 N개 접음 (전체 M개 항목, 계속 이어감)`으로
  표시하고, 진행 중/대기 항목은 그대로 보여 줍니다. 헤더의 진행률(`완료 12/58`)과
  에이전트가 보는 목록은 **전체 개수**를 유지하므로, 항목이 많아도 하나의
  작업(job)으로 끝까지 이어갑니다(항목 수/상태가 어긋나면 보정합니다).

#### 요약(압축)을 넘어 계획 이어가기

- 대화가 커져 **요약이 일어나도 작업 계획은 사라지지 않습니다.** 요약문에
  `[진행 중인 작업 계획 — 새로 만들지 말고 이 계획을 이어서 갱신하세요]` 블록
  (목표 + 현재 항목/상태)을 함께 넣어, 모델이 **같은 계획을 이어서** 갱신합니다.
- 요약문에는 기계용 스냅샷 `<!-- llm-todo:{...} -->`도 심습니다. 다음 실행이
  그 대화를 불러오면 계획을 **복원**해 새로 시작하지 않고, `ℹ️ 이어가는 작업
  계획: 전체 N개 (완료 M개)`로 알려 줍니다.
- **끝난 계획은 되살리지 않습니다(중요).** 모든 항목이 완료(done)된 계획은
  다음 실행에서 복원·이어가기 대상이 아니며, 저장할 때마다 요약 헤드의 스냅샷을
  **지금 계획으로 최신화**하고 계획이 끝났으면 헤드에서 계획 블록·스냅샷을
  **걷어냅니다**. 그래야 옛 목표(`🎯 …`)가 새 작업의 목표처럼 자동 설정되지
  않습니다(진행 중인 계획은 그대로 이어갑니다).
- 스냅샷을 복원할 때는 **가장 마지막에 파싱되는 것**만 씁니다. 도구 출력 등에
  우연히 섞인 스탬프 모양의 문자열(파싱 불가) 때문에 멀쩡한 계획을 잃지 않습니다.
- 요약 시 계획을 함께 실었으면 `ℹ️ 진행 중인 작업 계획을 요약에 함께 실어
  이어갑니다.`로 안내합니다.

### 잔액·소요 비용 표시 (`--no-balance`)

에이전트 모드는 **시작할 때 잔액을 조용히 조회해 캐시**하고(화면에는 표시하지
않음. 실패하면 경고만), 정상 종료하면(`작업 완료 (N단계)`) **최종 답변 직전에**
아래를 `--balance`와 같은 형식으로 보여줍니다.

```text
──────────────────────── 💵 DeepSeek 잔액 정보 ────────────────────────
  위안화 (CNY)  2.95 CNY
  미국달러 (USD)  0.99 USD
  원화 (KRW)  1,916.25 원  (환산)
────────────────────────────────────────────────────────────────────────
  적용 환율(실시간): 1 CNY = 199.43 KRW · 1 USD = 1,341.35 KRW   (Sat, 12 Sep 2026 00:02:31 +0000)
  소요 비용: 23.38 원 (0.05 CNY · 0.01 USD)   (시작 3.00 CNY · 1.00 USD → 종료 2.95 CNY · 0.99 USD)
  토큰 사용: 입력 4,484 · 출력 172 · 합계 4,656 토큰 · 캐시 적중 2,688 / 미적중 1,796 · API 3회
```

- **계정 잔액은 화폐별로 존재**할 수 있습니다(위안화 `CNY`, 미국달러 `USD`
  등). API가 준 **화폐별 잔액을 그대로** 보여주며, 없는 화폐는 표시하지
  않습니다(지어내지 않음).
- **환산해 보여주는 화폐는 원화(KRW) 하나**입니다. `원화 (KRW)` 줄이 화폐별
  잔액을 원화로 환산한 합계이고(옆에 `(환산)` 표시), 화폐별 금액은 각 줄에
  그대로 나옵니다.
- **환율은 실시간으로 조회**합니다(참고용): `RATE_URL`
  (`https://open.er-api.com/v6/latest/USD`, 키 불필요)에서 `1 USD` 기준 전 화폐
  시세를 받아 교차 환산해 `1 화폐 = 몇 원`을 만들고, 화면에는 `적용
  환율(실시간): …`과 **갱신 시각**을 함께 보여줍니다. 받은 시세는
  `RATE_CACHE_TTL`(12시간) 동안 `~/.local/share/llm/rates.json`에 캐시해
  재조회를 아낍니다.
  - 조회에 실패하면 (1) 캐시된 오래된 시세가 있으면 `(오래된 시세, 갱신 실패: …)`
    표시와 함께 그 값을 쓰고, (2) 없으면 **가정 환율**로 되돌아갑니다
    (`적용 환율(가정): …   (가정 환율 (실시간 조회 실패: …))`). 가정 환율은
    `CURRENCY_KRW_RATE` = `1 CNY = 220 KRW`(`KRW_PER_CNY`) · `1 USD = 1,350 KRW`
    (`KRW_PER_USD`)입니다.
  - `--no-rates`(또는 `LLM_RATES=0`)로 실시간 조회를 끄면 항상 가정 환율을
    씁니다(오프라인/고정값 선호 시).
  - 실시간 시세가 있으면 가정 환율에 없던 화폐(예: `JPY`)도 환산됩니다. 그래도
    모르는 화폐가 섞이면 그 줄에 `(환율 미지정)`을 붙이고 원화 합계는 `?`가
    됩니다.
- **소요 비용** = 시작 잔액 − 종료 잔액(화폐별로 계산해 원화로 환산).
  - 계정에 화폐가 하나뿐이면 그 화폐로도 보여줍니다: `0.05 CNY (11.00 원)`,
    `0.01 USD (13.50 원)`. 여러 화폐면 원화 합계를 앞세우고 화폐별 내역을
    괄호에 붙입니다: `24.50 원 (0.05 CNY · 0.01 USD)`.
  - 잔액이 **화폐 최소 단위(0.01)로만** 오므로, 환산액이 그 절반에도 못 미치면
    구분할 수 없습니다. 그때는 `소요 비용: 0.01 미만`과 함께 "정확한 비용은 알
    수 없습니다" 안내를 붙이고, 잔액이 늘었으면 `잔액 증가`로 표기합니다.
- **토큰 사용량**은 API 응답의 `usage`를 누적한 값입니다(입력/출력/합계,
  프롬프트 캐시 적중·미적중, API 호출 횟수). 스트리밍에서도 받도록
  `stream_options.include_usage`를 켭니다. 제공되지 않는 모델/버전에서는
  이 줄이 생략됩니다.
- 시작 잔액 조회에 실패하면 소요 비용만 생략하고 종료 잔액은 그대로 보여줍니다.
  종료 잔액 조회도 실패하면 경고만 출력하고 답변은 정상 표시됩니다.
- `--no-balance`는 **시작 잔액 조회와 종료 표시를 모두** 생략합니다(API 호출
  한 번을 아낌). `--chat` 모드에서는 푸터를 표시하지 않습니다(대신 기준 잔액만
  조용히 캐시해 `/cost`의 금액은 쓸 수 있습니다).

### 대화형 `/cost` — 세션 누적 소요 금액

토큰 단가표가 없으므로 **잔액 차이**로만 금액을 냅니다: **세션 시작 잔액(첫
성공 조회, `SESSION_BALANCE_BASE`) − 현재 잔액**, 원화로 환산.

```text
ℹ️ 토큰 사용: 입력 4,484 · 출력 172 · 합계 4,656 토큰 · 캐시 적중 2,688 / 미적중 1,796 · API 3회
  세션 소요 금액: 23.38 원 (0.05 CNY)   (시작 3.00 CNY → 현재 2.95 CNY)
```

- REPL 턴 푸터는 첫 턴에만 나오므로, **이어가는 턴의 금액은 `/cost`로 확인**합니다.
- 현재 잔액은 `COST_BALANCE_TTL`(5초) 동안 캐시해 연속 `/cost`가 API를 두드리지
  않습니다(`COST_BALANCE_CACHE`).
- 금액이 화폐 최소 단위(0.01)에 못 미치면 `0.01 미만`과 “정확한 금액은 알 수
  없습니다” 안내를 붙이고, 잔액이 늘었으면 `세션 잔액 증가`로 표기합니다.
- 금액을 낼 수 없으면 **이유를 한 줄로 안내**하고 지어내지 않습니다:
  `--no-balance`로 꺼져 있음 · API 키 없음 · 기준 잔액 없음(조회 실패) ·
  현재 잔액 조회 실패 · 잔액 형식 오류.
- 채팅 모드(`/chat`)도 시작 시 조용히 잔액을 한 번 조회하므로(푸터는 없음)
  `/cost`의 금액 줄은 동일하게 동작합니다.

### 대화형 `/balance` — 현재 잔액 보기

REPL 안에서 `llm balance` 와 **같은 블록**을 그 자리에서 보여 줍니다.
(화폐별 잔액 + 원화 환산 + 적용 환율, 아래에 세션 소요 금액 줄)

```text
llm:agent> /balance
ℹ️  DeepSeek 계정 잔액을 조회합니다...
──────────────── 💵 DeepSeek 잔액 정보 ────────────────
  위안화 (CNY)  2.95 CNY
  미국달러 (USD)  0.99 USD
  원화 (KRW)  1,916.25 원  (환산)
────────────────────────────────────────────────────────
  적용 환율(실시간): 1 CNY = 199.43 KRW · 1 USD = 1,341.35 KRW   (Sat, 12 Sep 2026 00:02:31 +0000)
  세션 소요 금액: 23.38 원 (0.05 CNY · 0.01 USD)   (시작 3.00 CNY · 1.00 USD → 현재 2.95 CNY · 0.99 USD)
```

- 조회값은 `COST_BALANCE_CACHE` 에 넣으므로 **직후 `/cost` 는 잔액을 다시
  호출하지 않습니다**(`balance_now`).
- 조회에 실패하면 경고 줄만 남기고 대화는 계속됩니다(`llm balance` 도 같음,
  종료 코드 1).
- `--no-balance` 로 시작했으면 호출하지 않고 이유만 안내합니다.

## 세션 규칙

프로젝트별 지침을 대화 기록과 별개로 코드 저장소에 남길 수 있습니다.
규칙은 **매 API 요청의 시스템 프롬프트에 포함**되어 모델이 따릅니다.

### 파일 위치

```
<작업폴더>/.llm/rules.md        # 기본 규칙 파일
<작업폴더>/.llm/rules/*.md      # 추가 규칙 (파일명 사전순으로 병합)
```

### 사용

```bash
# 템플릿 생성
llm rules init

# 현재 적용되는 규칙 확인
llm rules show
```

- 두 위치의 규칙을 합쳐 최대 `MAX_RULES_CHARS`(24,000자)까지 적용합니다.
- **프로젝트 지침 파일**도 함께 읽습니다(Claude Code·Codex 등과 공용):
  `~/.claude/CLAUDE.md`(전역) → 홈부터 작업 폴더까지 각 폴더의 `CLAUDE.md`,
  `AGENTS.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md` 순서로, 합계 24,000자까지.
  끄려면 `LLM_PROJECT_DOCS=0`. `llm rules show`에 적용 중인 파일이 표시됩니다.
- 규칙이 없으면 모델은 규칙 없이 동작합니다.
- "규칙을 수정해줘"라고 요청하면 에이전트가 해당 파일을 직접 편집합니다.

### 작성 예

```markdown
# 세션 규칙

## 프로젝트
- Python 3.10, 표준 라이브러리만 사용
- 패키지 구조는 src/ 아래 유지

## 코딩 규칙
- 편집은 str_replace 사용, 최소 변경
- 한글 응답

## 하지 말 것
- 의존성 추가 금지
- .env, 키 파일 출력 금지

## README
- 기능/옵션 변경 시 README.md를 즉시 갱신
```

> **이 저장소의 규칙**: `agent.py`의 기능, CLI 옵션, 동작이 바뀌면
> `README.md`를 **즉시** 갱신합니다. 자세한 내용은 `.llm/rules.md` 참고.

## 에이전트 도구

에이전트 모드에서 모델이 쓰는 도구입니다(v0.7: **7개**). 경로는
**워크스페이스 안**만. 예전 이름(`read_file`, `str_replace`, `grep`, `multi_edit` …)도
alias로 동작합니다.

| 도구 | 설명 | 주요 인자 |
|------|------|-----------|
| `todo` | 짧은 작업 계획(여러 단계일 때) | `goal`, `items` |
| `read` | 파일 읽기 (2,000자 넘는 줄은 자름) | `path`, `offset`, `limit` |
| `edit` | 수정 · `action=replace\|write\|delete`. **기존 파일은 먼저 read** | `path`, `old_string`/`new_string` 또는 `edits`(배열) 또는 `contents` |
| `find` | 탐색 · `mode=list\|glob\|grep` | `path`, `pattern`, `glob`, grep 전용 `output=content\|files\|count`·`context`·`max_results` |
| `shell` | bash (테스트·git·빌드). 파일 I/O에는 쓰지 말 것 | `command`, `timeout`(최대 600초), `background`, `bg_id`, `kill` |
| `web_fetch` | URL 본문을 텍스트로(HTML → 읽기 좋은 텍스트). 호스트별 첫 요청 시 `[y/N/a]` 확인 | `url`, `max_chars` |
| `task` | 읽기 전용 **서브에이전트**에게 조사를 맡기고 보고서만 받음(메인 맥락 절약) | `description`, `prompt` |

### 편집 안전장치와 되돌리기

- **읽은 파일만 편집**: 에이전트가 `read`(또는 `@멘션` 첨부)하지 않은 기존 파일은
  `edit`가 거부합니다. 새 파일 작성은 예외. 끄려면 `LLM_EDIT_REQUIRE_READ=0`.
- **바깥 변경 감지**: 읽은 뒤 사용자·다른 프로그램이 파일을 바꾸면(mtime/크기) 다시
  읽으라고 돌려보내 덮어쓰기 사고를 막습니다.
- **diff 표시**: 모든 편집은 색 diff(최대 60줄)를 보여주고, 결과에 `+추가 -삭제`를 남깁니다.
  `--confirm-edits`(또는 `--confirm-all`)이면 적용 전에 `[y/N/a]`로 묻습니다.
- **다중 치환**: `edits` 배열은 차례로 적용하며 **하나라도 실패하면 아무것도 바꾸지 않습니다**.
- **줄바꿈 보존**: CRLF 파일도 그대로 유지(LF로 보낸 치환은 CRLF로 맞춰 적용).
- **되돌리기**: 턴마다 편집 전 원본을 `~/.local/share/llm/undo/undo_<세션>.json`
  (최근 20턴, 파일당 2MB까지)에 저장합니다. `llm undo`/`/undo`는 **마지막 편집 턴**의
  파일을 원래대로(새로 만든 파일은 삭제) 되돌리고, 편집 뒤 다시 바뀐 파일이 있으면
  경고합니다. 되돌린 사실은 다음 요청에 자동으로 알려 모델이 다시 읽게 합니다.
  **셸로 바꾼 파일은 추적하지 않으니** git 으로 되돌리세요.

### 병렬 실행·서브에이전트·백그라운드 셸

- 한 응답에 `read`/`find`/`task`만 여러 개 오면 **동시에 실행**합니다(최대 8개).
  셸·편집·웹처럼 확인이 필요할 수 있는 도구가 섞이면 순서대로 실행합니다.
- `task` 서브에이전트는 독립된 대화에서 `read`/`find`/읽기 전용 `shell`/`web_fetch`만
  쓰며(최대 25단계), 편집·비밀 노출 명령·재귀 `task`는 거부됩니다.
- `shell(background=true)`는 서버·watch 같은 명령을 띄우고 `bg_1` 같은 id를 돌려줍니다.
  `shell(bg_id="bg_1")`로 새 출력·상태를, `kill=true`로 종료합니다. llm이 끝나면
  함께 정리됩니다. REPL `/bg`로 목록을 봅니다.

### 맥락 관리

- **토큰 기준 압축**: API가 알려준 실제 입력 토큰이 `LLM_COMPACT_TOKENS`(기본 90,000)를
  넘으면 문자 수와 무관하게 요약·압축합니다(기존 문자 수·메시지 수 기준도 유지).
- **오래된 도구 결과 비우기**: 도구 결과 합계가 60,000자를 넘으면 최근 6개를 뺀
  1,500자 이상 결과를 `[이전 도구 결과 비움: …]`로 **한꺼번에** 바꿔 저장합니다
  (조금씩 비우면 매 단계 프롬프트 캐시가 깨지므로 일괄 처리).
- **`@파일` 멘션**: 프롬프트의 `@경로`는 파일 내용(폴더면 목록)을 첨부합니다(최대 10개,
  60,000자). 이메일(`a@b.com`)·워크스페이스 밖·비밀 파일은 첨부하지 않습니다.

### 제약

- 경로는 워크스페이스 밖으로 나갈 수 없습니다.
- `.env`, `.env.*`(`.env.example` 등 견본 제외), `credentials.json`, `id_rsa`,
  `*.pem`, `*.key`, `.netrc`, `.npmrc`, `.pypirc`, `.ssh/*` 등
  비밀/자격 증명 파일은 도구로 접근할 수 없고 `find grep` 결과에서도 빠집니다.
- 읽기/도구 출력은 각각 `MAX_READ_BYTES`(200KB), `MAX_TOOL_CHARS`(80KB),
  grep은 `MAX_GREP_HITS`(80, `max_results`로 최대 500)로 제한됩니다. 큰 파일은 offset/limit을 사용합니다.

## 셸 실행과 안전장치

`shell` 도구는 다음 안전장치를 가집니다.

0. **비밀값 보호(v0.7, 모든 모드 공통)**
   - 셸 하위 프로세스 환경에서 이름에 `API_KEY`·`ACCESS_KEY`·`SECRET`·`TOKEN`·
     `PASSWORD`·`CREDENTIAL`·`PRIVATE_KEY`가 들어간 변수를 뺍니다. 꼭 넘겨야 하면
     `LLM_SHELL_KEEP_ENV=GH_TOKEN,NPM_TOKEN`처럼 지정합니다.
   - `cat .env`, `echo $DEEPSEEK_API_KEY`, `printenv`, `env`, `export -p`,
     `~/.ssh/*`·`/etc/env/*` 참조처럼 **비밀을 드러낼 수 있는 명령은 자동 허용
     목록·`--trust`와 상관없이 매번 `🔐` 확인**을 받습니다(`--yes`만 생략, TTY가 아니면 거부).
   - 모든 도구 결과에서 알려진 비밀값(비밀 이름 환경변수 값, `.env` 파일의 키 값·
     토큰처럼 생긴 값)을 `[REDACTED]`로 가린 뒤 모델에 보내고 기록에 저장합니다.
   - 셸은 표준입력이 닫힌 상태(`/dev/null`)로 실행되어 입력 대기로 멈추지 않습니다.

1. **자동 실행 범위(기본값 = safe)** — 작업 폴더 안에서 끝나는 명령은 확인
   없이 실행하고, 폴더 밖·설치·`sudo` 등은 확인합니다(`--safe`). 더 관대하게
   쓰려면 `--trust`, 전부 확인하려면 `--confirm-all`을 씁니다.
   - 확인 대상(권한 상승): `sudo`, `su`, `doas`, `pkexec`
   - 확인 대상(설치·패키지): `apt`/`pip`/`npm install` 등
   - 확인 대상(폴더 밖 삭제): 워크스페이스 밖 `rm`/`rmdir` 등
   - 위험 패턴(`rm -rf /`, `mkfs.*`, …)은 어느 모드에서도 차단
2. **위험 패턴 차단** — 실행 전 금지 패턴 검사
   (예: `rm -rf /`, `mkfs.*`, `dd of=/dev/*`, fork bomb, `shutdown/reboot` 등)
3. **읽기 전용/검증 명령 자동 실행** — 아래 화이트리스트에 해당하면 확인 없이
   바로 실행합니다(실행 전에 무엇을 하는지 한 줄로만 안내).
   - 조회 계열: `ls`, `cat`, `head`, `tail`, `wc`, `grep`, `find`, `stat`,
     `pwd`, `echo`, `env`, `which`, `file`, `du`, `df`, `date`, `cd`, `sleep` 등
   - 조회 계열 2단어 조합: `pip list`, `pip show`, `node -v`, `rustc --version`,
     `tsc --noEmit`, `java -version` 등 (`SHELL_SAFE_PAIRS`)
   - 서브커맨드 조회/검증: `npm ls`, `npm test`, `cargo test`, `cargo check`,
     `go build`, `docker ps`, `kubectl get`, `systemctl status` 등
     (`SHELL_SAFE_SUBCOMMANDS`)
   - 테스트/린트/타입 검사: `pytest`, `ruff check .`, `flake8`, `mypy`, `eslint`,
     `shellcheck`, `gofmt`, `black --check`, `prettier --check`
     (`--fix`/`--write`/`-w`처럼 파일을 고치는 플래그가 있으면 확인 필요,
     `SHELL_SAFE_CHECKERS`/`SHELL_CHECK_WRITE_FLAGS`)
   - 프로젝트 스크립트: `npm test`, `npm run <test|lint|build|typecheck|...>`,
     `make <test|build|check|lint|...>` (`SHELL_SAFE_RUN_SCRIPTS`/`SHELL_SAFE_MAKE_TARGETS`)
   - Git 조회·스테이징: `git status`, `git log`, `git diff`, `git show`,
     `git branch`, `git add` (index만 변경, `git reset`으로 되돌림)
     — `commit`/`push`/`pull`/`checkout`/`reset`/`clean`/`stash`는 확인 필요
   - Python 조회: `python3 -m py_compile`, `python3 -m json.tool`, `python3 -m unittest`,
     `python3 script.py`, `python3 --version` 등 (`-c`/`-i` 같은 임의 코드 실행은 확인 필요)
   - 버전/도움말: `git --version`, `cargo --version`, `docker --version` 등
     (경로 실행 `./run.sh --version`은 제외)
   - 연결 명령(`&&`, `|`): **모든 조각이 자동 실행 대상일 때만** 자동 실행합니다.
     예) `git add -A && pytest -q`, `ls -la | head -5`는 자동 실행,
     `ls && rm -rf x`, `pytest -q && npm install`은 확인 대상.
     `;`(순차 연결)은 항상 확인 대상입니다.
   - 리다이렉션은 위험 판정(`> out.txt` 등), `/dev/null`·`2>&1`은 무해 처리
   - 환경변수 접두: `FOO=1 npm test`처럼 앞에 지정이 붙어도 프로그램을 보고
     같은 기준으로 판단합니다(`PATH`/`LD_PRELOAD`/`PYTHONPATH` 등 실행 대상을
     바꾸는 이름이 붙으면 확인 대상)
   - `--confirm-all`로 자동 실행을 끌 수 있습니다. **대화형(`llm`/`llm repl`/`llm agent`)은
    기본이 `readonly`(읽기 전용 자동)** — 조회·검사 명령은 조용히 실행하고 그
    밖은 확인하며, 시작할 때 현재 설정을 시작 헤더의 `셸`·`완화`·`로그` 행으로
   보여 줍니다
    (`llm --safe/--trust/--yes/--confirm-all`이나 `LLM_*` 환경변수를 직접 주면
    그쪽을 따릅니다).
4. **사용자 확인** — 자동 실행 대상이 아니면 TTY에서 `[y/N/a]` 확인을 받습니다.
   프롬프트에는 **실제로 실행될 명령**만 보여줍니다(무엇을 하려는지는 위의
   `🔧 shell <의도 요약>` 줄에 이미 표시됩니다).
   - `&&`, `||`, `|`, `;`로 이어진 조합 명령은 한 덩어리로 묻지 않고 **조각
     단위로 하나씩** 묻습니다(`1)`, `2)` …). 각 조각에 `y`(이번만) / `a`(그
     조각 자동 허용) / `n`(전체 중단). 같은 프롬프트에서 남은 조각을 한꺼번에
     넘기려면 `all`(저장하지 않음, 아래 5번 참고).
     `n`으로 중단하면 **그 프롬프트에서 `a`로 추가한 항목은 되돌립니다**(전에
     허용해 둔 항목은 유지).
5. **자동 허용 목록(`a`)** — 확인 프롬프트에서 `a`를 고르면 같은 명령을
   **다시 묻지 않고** 실행합니다. `--yes`와 달리 명령별로만 허용되며
   세션별 파일에 저장됩니다.
   - 저장 범위: 위험하지 않은 명령은 **"계열"**(`npm install` 등 앞 두 토큰)로
     저장해 `npm install -g x`, `npm install --save y`를 함께 허용하고, 정확히
     한 단어뿐이거나 서브커맨드가 없는 명령(`pytest`, `make` 등)은 정확
     일치로 저장합니다.
   - **폴더 범위**: 대상 경로가 분명한 위험 명령(`rm`, `rmdir`, `mv`, `cp`,
     `mkdir`, `touch`, `shred`, `truncate`, `sed`, `tee` …)은 **그 폴더 이하를
     한꺼번에** 허용합니다. 예를 들어 `rm -rf build/a.txt`를 `a`로 허용하면
     `build/` 안의 `rm`은 인자가 달라도 다시 묻지 않습니다(프롬프트에
     `a = 이 명령 + rm (build/ 이하) 자동 허용`으로 표시).
     홈·작업 폴더·`/`·`/tmp` 같은 루트, 경로가 여러 폴더로 갈리거나 `$VAR`로
     숨겨진 경우에는 폴더 범위를 만들지 않습니다(정확 일치만).
   - `all`은 `a`와 달리 **저장하지 않고 이번 실행 동안만** 확인을 생략합니다
     (`llm`을 끝내면 해제). 급할 때 한 번 쓰기 좋습니다.
   - **조각별 저장**: 조합 명령은 조각마다 따로 기억합니다. `npm run build &&
     docker build -t app .`의 두 조각을 각각 `a`로 허용하면, 순서를 바꾸거나
     인자가 달라져도(`docker build -t app:v2 . && npm run build`) 다시 묻지
     않습니다.
   - **환경변수 접두**: `FOO=1 npm run build`처럼 앞에 환경변수 지정이 있으면
     프로그램(`npm run`) 기준으로 접두를 만들고, 같은 이름이 붙은 변형도 함께
     허용합니다. 다만 `PATH`, `LD_PRELOAD`, `PYTHONPATH`, `GIT_SSH_COMMAND`
     처럼 실행 대상·로딩을 바꾸는 이름이 붙으면 계열 허용하지 않습니다
     (정확 일치만). 같은 기준이 읽기 전용 자동 실행과 `--safe`(작업 폴더 안 자동)
     판정에도 적용됩니다.
   - 허용 제외: `rm`, `sudo`, `curl`, `dd`, `chmod` 등 위험 프로그램은 계열
     허용하지 않습니다(정확 일치만). 조각 안에 리다이렉션(`>`), 백그라운드
     (`&`), 명령 치환(`$()`, 백틱)이 남아 있으면 계열 허용하지 않습니다.
     프롬프트에는 계열 허용이면 `a = 이 명령/<접두> 계열 자동 허용`,
     정확 일치면 `a = 이 명령만 자동 허용`으로 표시됩니다.
   - 인자에 따라 쓰기로 바뀌는 명령도 계열 허용하지 않습니다. 검사 도구의
     `--fix`/`-w`/`--install-types`, `find -exec`/`-delete`, `--in-place`,
     `--output`처럼 부작용을 켜는 인자가 붙으면 매번 확인합니다
     (예: `ruff check .`을 허용해도 `ruff format .`은 확인 대상).
   - 목록 확인/해제: `llm shell allow`, `llm shell allow clear`
6. **권한 상승(`sudo` 등) — 목적 설명 후 항상 확인** — 명령에 `sudo`/`su`/`doas`/
   `pkexec` 조각이 있으면 다른 모드·허용과 상관없이 **전용 프롬프트**가 뜽니다
   (`--yes`만 생략). 무엇을 위해 필요한지 목적을 함께 보여 주므로, 명령만 보고
   판단하지 않아도 됩니다.

   ```text
   🔐 관리자 권한이 필요합니다 (sudo)
      목적: 패키지를 설치하거나 관리합니다
      실행할 명령: sudo apt install -y jq
      권한 상승은 자동 허용으로 저장되지 않습니다(매번 확인)
      [y/N]:
   ```

   - 목적은 권한 상승으로 실제 실행되는 명령에서 뽑습니다
     (`sudo -u root apt install jq` → “패키지를 설치하거나 관리합니다”,
     `sudo systemctl restart nginx` → “서비스를 제어합니다”). 알려지지 않은
     명령은 “<명령> 명령을 관리자 권한으로 실행합니다”, `sudo -i`처럼 대상이
     없으면 “sudo 로 관리자 권한(셸)을 얻습니다”.
   - 답은 `y`/`n` 뿐입니다(`a`·`all` 없음). 앞에서 `all`을 골라 이번 실행의
     확인을 생략한 상태라도 **`sudo`는 다시 묻습니다**(`llm --trust`도 같음).
   - 같은 이유로 `sudo`는 **읽기 전용 자동 실행 대상이 아닙니다** — `sudo ls`도
     매번 확인합니다.
7. **TTY가 아니면** `--yes` 없이 실행 불가
8. **타임아웃** — 기본 60초, 최대 180초

### 프롬프트가 뜨는 기준 (기본 모드)

기본(허용) 모드에서는 **`sudo`·설치·폴더 밖 삭제 조각만** 프롬프트가 뜹니다.
나머지 조각은 조용히 실행되므로, 조합 명령에서도 물어보는 횟수가 적습니다.

```
🔧 shell 저장소를 살펴봅니다
❓ 확인이 필요합니다 (조각 3개 중 1개 확인)
   전체: git status && pip install requests && ls
   2) 실행할 명령: pip install requests
   a = 이 명령/pip install 계열 자동 허용 (다시 묻지 않음)
   all = 이번 실행 동안 확인 생략 (저장하지 않음)
   [y/N/all/a]: y
```

폴더 밖 파일 삭제처럼 대상 경로가 분명한 명령은 `a`가 **그 폴더 전체**를 기억해
같은 폴더 안의 반복 작업을 묶어 줍니다(묶을 수 없으면 `a = 이 명령만 자동 허용`).

```
❓ 확인이 필요합니다
   실행할 명령: rm -rf /srv/app/build/a.txt
   a = 이 명령 + rm (/srv/app/build/ 이하) 자동 허용
   all = 이번 실행 동안 확인 생략 (저장하지 않음)
   [y/N/all/a]: a
✅ 자동 허용에 추가했습니다: rm (/srv/app/build/ 이하) (해제: llm shell allow clear)
```

`--confirm-all`을 쓰면 아래 예시처럼 위험 조각까지 묻습니다.

### 확인 프롬프트 예시 (조합 명령)

도구 호출 줄에서 무엇을 하려는지 먼저 요약해 보여주고, 확인이 필요한 경우에만
프롬프트가 뜹니다. 조합 명령은 조각 단위로 하나씩 묻습니다.

```
🔧 shell 빌드를 실행합니다 → 컨테이너를 다룹니다
❓ 확인이 필요합니다 (조각 2개 중 2개 확인)
   전체: npm run build && docker build -t app .
   1) 실행할 명령: npm run build
   a = 이 명령/npm run 계열 자동 허용 (다시 묻지 않음)
   [y/N/all/a]: a
   2) 실행할 명령: docker build -t app .
   a = 이 명령/docker build 계열 자동 허용 (다시 묻지 않음)
   [y/N/all/a]: a
✅ 자동 허용에 추가했습니다: npm run, docker build (해제: llm shell allow clear)
```

단일 명령이면 이전처럼 한 번만 묻습니다(`[y/N/a]`, `all` 없음). 조각마다 `a`를
고르면 조각별로 저장되므로 **조합 순서나 인자가 바뀌어도** 이미 허용한 조각은
다시 묻지 않습니다(예: `docker build -t app:v2 . && npm run build`는 바로 자동
통과). 위험 프로그램(`rm`, `mv` 등)은 `a`로 **폴더 범위**를 잡거나 정확히 같은
명령일 때만, 리다이렉션·명령 치환이 섞인 조각은 정확히 같은 명령일 때만 자동
통과합니다. 파일을 만드는 heredoc(`cat > f <<'PY'`)은 본문이 실행 코드가 아니라
데이터이므로 기본 모드에서 묻지 않습니다(아래 「heredoc·인라인 스크립트 처리」).
확인이 자주 뜨는 반복 작업이 많으면 `--trust`(또는
`LLM_ALLOW_ALL=1`)를 쓰세요.

### REPL 기본 확인 모드와 셸 로그

`llm`(인자 없음) / `llm -i` / `llm repl` / `llm agent`(대화형)는 한 프로세스에서
여러 턴을 이어가며 셸을 자주 부르므로 **기본을 `readonly`(읽기 전용 자동)로 둡니다**
— `ls`·`cat`·`git status/diff/log`·테스트처럼 읽기만 하는 명령은 조용히 실행하고,
그 밖의 명령(설치·삭제·`git commit` 등)은 확인을 받습니다. 권한 상승(`sudo` 등)은
대상이 읽기 전용이어도 **항상 목적 설명과 함께 확인**을 받습니다.
1턴 실행(`llm ask "질문"`)은 작업 폴더 안까지 자동인 `safe`가 기본입니다.
`--safe`/`--trust`/`--yes`/`--confirm-all`이나 `LLM_AUTO_WORKSPACE` 같은
`LLM_*` 환경변수를 **직접 주면 그쪽을 따릅니다**(repl 기본은 그때 쓰지 않음).
다시 “전부 확인”으로 돌리려면 `llm repl --confirm-all`을 쓰세요.

시작할 때 현재 설정을 시작 헤더의 행으로 보여 줍니다.

```text
  셸        확인=읽기 전용 자동 (repl 기본)
  완화      --safe / --trust / --yes (셸 확인 완화) · sudo 등 권한 상승은 목적 설명 후 매번 확인
  로그      ~/.local/share/llm/shell_log_llm.jsonl (기록 켬 · 조회 /log)
```

확인 프롬프트에서 허용한 명령과, 허용 목록(`a`) 덕분에 프롬프트 없이 실행된
명령은 **세션별 로그**에 한 줄씩 남습니다(`shell_log_<세션>.jsonl`).

| 종류 | 표시 | 언제 |
|------|------|------|
| `auto` | 자동 허용 실행 | 자동 허용 목록에 있어 **묻지 않고** 실행됨 |
| `a` | 자동 허용 추가 | 이번 프롬프트에서 `a`(그 명령/계열 자동 허용) |
| `all` | 이번 실행 생략 | 이번 실행 동안 생략(`all`) |
| `y` | 이번만 허용 | 이번만 실행(`y`) |
| `n` | 거부 | 거부(`n`) |

```text
$ llm shell log            # 또는 REPL 에서 /log  (최근 20건, llm shell log 50)
─────────────────── 셸 허용 로그  [llm]  최근 3/3건 ───────────────────
ℹ️  자동 허용 실행 1 · 이번만 허용 1 · 거부 1
   02-05 11:22  자동 허용 실행 npm test
   02-05 11:20  이번만 허용   git pull --ff-only
   02-05 11:18  거부       rm -rf /srv/app (취소)
ℹ️  파일: ~/.local/share/llm/shell_log_llm.jsonl
ℹ️  비우기: llm shell log clear
```

- 기록은 **부가 기능**이라 쓰기에 실패해도 셸 실행을 막지 않습니다.
- 최근 500건까지만 남기고, 명령은 500자까지만 저장합니다.
- `LLM_SHELL_LOG=0`이면 새 기록을 남기지 않습니다(기존 파일은 조회 가능).
- 비우기: `llm shell log clear` (REPL 은 `/log clear`).
- 기록 파일은 기기 로컬 정보라 대화 기록 위치(`LLM_HISTORY`)와 무관하게 홈에 둡니다.

### heredoc·인라인 스크립트 처리

`cat > f.txt <<'EOF' … EOF`, `python3 - <<'EOF' … EOF`처럼 heredoc으로 넘기는
**본문은 데이터로 보고** 설치·삭제 패턴을 스캔하지 않습니다(본문에 `pip install`
문구가 있어도 설치로 오해해 묻지 않습니다). 그래도 아래는 확인 대상입니다.

- `bash <<'EOF'`, `sh`, `zsh`, `source`, `eval`, `sudo` 등 **본문이 그대로 코드로
  실행되는 경우**
- `python3 -c '...'`, `node -e`, 인터프리터 단독 실행(`python3 -`, 파이프 입력)
- `./run.sh`, `sh run.sh`처럼 **스크립트 파일 직접 실행**(내용을 검증할 수 없음)

`--safe`(작업 폴더 안 자동) 모드에서는 경로를 붙인 인터프리터
(`./.venv/bin/python - <<'EOF'` 등)를 `python3 - <<'EOF'`와 **같은 기준**으로
판단합니다(스크립트 실행과 동급). `-c`/`-e`로 코드를 넘기면 확인 대상입니다.

### 작업 폴더 안 자동 실행 (`--safe`)

`--safe`(기본)를 켜면 **명령이 건드리는 경로가 전부 작업 폴더 안에서
끝나고, 되돌릴 수 있는 명령이면** 확인 없이 실행합니다. "폴더 안이면 다
허용"에 가깝지만 아래 조건으로 범위를 막습니다.

- 자동 실행되는 예: `rm -rf build`, `mkdir -p src/new`, `mv a.py b.py`,
  `sed -i s/a/b/ main.py`, `echo hi > out.txt`, `ruff format .`, `black .`,
  `npm test > out.txt`, `git add -A`, `git commit -m wip`, `git tag v1`,
  `find . -name '*.py'`, `make test > log.txt`
- 그래도 확인하는 경우:
  - **작업 폴더 밖을 건드림**: `rm -rf ../x`, `cp a.py /tmp/x`, `> /etc/hosts`,
    `~/...`, `/opt`, 변수·명령 치환(`$VAR`, `` `...` ``)으로 경로를 숨긴 명령
  - **설치·네트워크·권한 상승**: `sudo`, `apt`/`pip install`/`npm install`,
    `curl`/`wget`/`git clone`, `docker`/`kubectl`/`systemctl`, `kill`/`pkill`
  - **되돌릴 수 없는 Git 작업**: `push`, `pull`, `fetch`, `checkout`, `switch`,
    `restore`, `reset`, `clean`, `stash`, `rm`, `filter-branch`, `--amend`,
    `--force`, `--hard`, `--global`
  - **`.git`/`.`/`*` 삭제·이동**: `rm -rf .git`, `rm -rf .`, `rm -rf *`,
    `mv .git x`
  - **임의 코드 실행**: `bash run.sh`, `sh -c`, `./run.sh`, `python3 -c`,
    `node -e`, 인터프리터 단독 실행, 스크립트 파일 직접 실행.
    heredoc 본문이라도 그대로 실행되는 경우(`bash <<'EOF'`)는 포함됩니다
    (자세한 기준은 위 「heredoc·인라인 스크립트 처리」).
  - **쓰기 옵션을 켠 `find`**: `find . -exec rm {} +`, `find . -delete`,
    `find . -ok ...`
  - **실행 대상을 바꾸는 환경변수 접두**: `PATH=/evil npm test`,
    `LD_PRELOAD=...`, `PYTHONPATH=...` (일반 지정 `FOO=1 cmd`는 프로그램 기준
    으로 판단)
- `--confirm-all`과 함께 쓰면 `--safe`는 무시됩니다(모두 확인).
- 매번 플래그를 치기 번거로우면 저장소 폴더의 `.env`(또는 `/etc/env/.env`)에
  `LLM_AUTO_WORKSPACE=1`을 넣어 기본으로 켜 둘 수 있습니다(`--confirm-all`이
  항상 우선).
- `--yes`처럼 확인 자체를 없애지는 않으므로, 위험한 명령은 그대로
  `[y/N/a]` 프롬프트를 거칩니다.

### 확인이 필요한 명령 (엄격 모드)

`--safe`처럼 자동 실행 화이트리스트를 쓰는 모드에서는 아래 명령이
`[y/N/a]` 확인 대상입니다(필요하면 `a`로 세션 한정 자동 허용). **기본(허용) 모드**
에서는 여기 있는 명령도 `sudo`·설치·폴더 밖 삭제가 아니면 그냥 실행됩니다.

| 분류 | 예 | 이유 |
|------|-----|------|
| 삭제·덮어쓰기·권한 | `rm`, `rmdir`, `mv`, `cp`, `truncate`, `dd`, `shred`, `chmod`, `chown`, `tee` | 되돌리기 어렵거나 데이터 손실 |
| 다운로드·설치·전송 | `curl`, `wget`, `pip install`, `npm install`, `npm ci`, `uv pip install`, `poetry install`, `apt install` | 외부 통신, 환경 변경 |
| 원격·이력 변경 | `git commit`, `git push`, `git pull`, `git fetch`, `git checkout`, `git switch`, `git reset`, `git clean`, `git stash` | 이력/원격 상태 변경 |
| 임의 코드 실행 | `bash run.sh`, `sh -c`, `bash <<'EOF'`(본문 실행), `./run.sh`, `python3 -c`, `node -e`, `eval`, `sed -i`, `awk`, `xargs` | 무엇이든 실행될 수 있음 |
| 서비스·컨테이너 변경 | `docker run/build`, `kubectl apply/delete`, `systemctl restart`, `kill`, `pkill` | 실행 중인 환경에 영향 |
| 파일을 고치는 검사 | `ruff check --fix`, `eslint --fix`, `black .`, `cargo fmt` | 검사 도구지만 파일 수정 |
| 위험 조각이 섞인 연결 | `ls && rm -rf x`, `pytest -q && npm install`, `ls; cat f`(`;`) | 한 조각이라도 위험하면 그 조각은 확인 |

그 밖의 명령(예: `make install`, `make clean`, `npm run deploy`)도 엄격 모드에서는
확인 대상이며, 조각마다 `y`(이번만) / `a`(그 조각 자동 허용) / `n`(전체 거부)
중에서 고릅니다(조합 명령이면 `all`로 남은 조각을 한꺼번에 허용).
`llm --yes`는 모든 확인을 건너뜁니다.

`llm shell allow`는 저장된 범위를 세 종류로 나눠 보여 줍니다.

```text
셸 자동 허용 목록  [llm]
   계열  npm install (...)
   폴더  mkdir (/srv/app/build/ 이하)
   폴더  rm (build/ 이하)
   정확  git push origin main
파일: ~/.local/share/llm/shell_allow_llm.json
해제: llm shell allow clear
```

계열 접두에 포함되는 정확 항목은 목록에서 숨깁니다(`llm shell allow clear`로 한 번에
비웁니다). 폴더 범위는 작업 폴더 기준 상대 경로(`build/`)로, 밖이면 절대
경로로 표시합니다.

| `LLM_PYTHON` | `python3` | `llm` 래퍼가 실행할 Python 실행기(3.10+). macOS 등에서 기본 `python3`가 3.9일 때 `LLM_PYTHON=python3.12` 처럼 지정 |
| `LLM_HISTORY_DIR` | (빈 값) | **대화 기록 로컬 저장 디렉터리**. 절대경로 권장(예: `/data/llm-sessions`); 상대경로는 실행 중인 작업 폴더 기준. 비워두면 `<작업폴더>/.llm/` | 
| `LLM_HISTORY` | (미설정) | 이전 버전 호환: `LLM_HISTORY_DIR`이 비어 있을 때만 `home`이면 `~/.local/share/llm/` 사용 |
| `LLM_AUTO_SYNC` | (꺼짐) | 보안상 항상 비활성화(설정해도 대화 기록 Push 안 함) |
| `LLM_AUTO_PULL` | (비활성화) | 보안상 대화 기록 자동 Pull 없음 |
| `LLM_AUTO_PULL_TTL` | `120` | 호환성 설정(대화 기록 자동 Pull 비활성화) |
| `NO_COLOR` | (미설정) | 설정 시 색상 출력 비활성화 |
| `LLM_CONFIRM_EDITS` | (꺼짐) | `1`이면 `--confirm-edits` (편집마다 diff 확인) |
| `LLM_EDIT_REQUIRE_READ` | `1`(켜짐) | `0`이면 읽지 않은 파일 편집 허용(v0.6 동작) |
| `LLM_RETRIES` | `4` | API 429/5xx/네트워크 오류 재시도 횟수 |
| `LLM_COMPACT_TOKENS` | `90000` | 실제 입력 토큰이 이 값을 넘으면 대화 압축 |
| `LLM_PROJECT_DOCS` | (켜짐) | `0`이면 `CLAUDE.md`/`AGENTS.md` 프로젝트 지침을 읽지 않음 |
| `LLM_SHELL_KEEP_ENV` | (없음) | 셸에 그대로 넘길 비밀 변수 이름(쉼표 구분). 기본은 모두 제거 |
| `LLM_SHELL_LOG` | `1`(켜짐) | `0`이면 셸 허용/실행 로그를 남기지 않음 (`llm shell log` 조회는 유지) |

`.env` 파일은 아래 순서로 로드됩니다(**앞이 우선**, 이미 설정된 환경변수는
덮어쓰지 않음).

1. `LLM_ENV_FILE`로 지정한 경로
2. 저장소 폴더의 `.env` (`llm`/`agent.py`가 있는 폴더)
3. `/etc/env/.env` (시스템 공용 폴백)

`LLM_AUTO_WORKSPACE=1`이 남아 있어 확인(`y/N`)이 자주 뜬다면 저장소 폴더의
`.env`(또는 `/etc/env/.env`)에서 그 줄을 지우거나 `0`으로 바꾸세요. 이번 실행만
바꾸려면 `llm --trust`(관대)나 `llm --confirm-all`처럼
**CLI 옵션을 직접 주면 환경변수를 이깁니다**. 현재 모드는 시작 헤더의
`셸` 행(`확인=…`)에서 바로 확인할 수 있습니다.

### 처리 흐름 (에이전트 모드)

0. 세션 결정: 이 폴더의 매핑을 쓰고, 없으면 새 세션을 만든다. 이때 사라진
   폴더의 매핑(고아)이 있으면 이어받을 후보를 보여주고 확인받는다
   (`apply_move_binding` → 이후 세션 안내). 조회/정리 명령도 같은 후보를 안내한다.
1. `@멘션` 파일을 첨부하고 undo 턴을 시작한 뒤, 사용자 프롬프트를 세션 기록에 추가하고
   저장(직전 턴이 답 없이 끝났으면 같은 user 메시지로 합침)
2. (잔액 표시가 켜져 있으면) 실시간 환율을 준비하고 시작 잔액을 조회해 캐시
   (화면에는 출력하지 않음). 채팅 모드는 조용히(경고 없이) 캐시만 하고,
   성공한 첫 조회는 `/cost` 기준 잔액(`SESSION_BALANCE_BASE`)으로도 남긴다
3. 시스템 프롬프트(워크스페이스 정보 + plan 모드 안내 + CLAUDE.md/AGENTS.md + 세션 규칙) 구성. 요약문에 남은 작업
   계획 스냅샷이 있으면 복원해(`restore_todo`) **같은 계획을 이어감**
4. 모델 호출 → (사고/작성 진행 상태 한 줄) → 텍스트 또는 도구 호출 수신
5. 도구 호출이면 `🔧 이름 <의도 요약>` 줄을 열고, 실행 후 같은 줄에
   `✓/✗ 결과 요약`을 붙여 **그 자리에서 갱신**한 뒤 결과를 대화에 추가해 4로
   반복 (셸은 확인이 필요할 때만 명령 원문 프롬프트). 계획(todo)이 있으면 이
   줄이 **진행 중인 항목의 하위 로그**로 붙고, 없으면 단계 머리말 아래에 그린다
6. 단계 시작 시 대화가 커졌으면 요약하고, 진행 중인 작업 계획(목표 + 항목)을
   요약문에 함께 실어 다음 단계에서도 같은 계획을 이어감
7. 최종 텍스트 응답을 저장하고 내장 렌더러로 Markdown 출력 (앞에 `작업 완료 (N단계)`,
   잔액·소요 비용·토큰 사용량 푸터). 작업 계획 블록은 지우지 않고 화면에 남긴다

반복이 `--max-steps`(기본 100)에 도달하면 곧바로 끝내지 않고 **이어서 같은
횟수만큼 더 진행할지 `[y/N]`으로 묻는다**(`ask_continue_steps`). `y`면 한도를
같은 값만큼 늘려 계속하고, `N`이면 그때까지의 기록을 저장한 채 멈춘다.
대화 기록은 저장돼 있으므로 이어서 요청을 보내면 계속 진행된다. TTY가
아닌 환경(파이프·자동화)에서는 물어볼 수 없으므로 자동으로 중단한다.

## 문제 해결

### `llm: command not found`

- `~/bin`이 PATH에 없을 수 있습니다.
  ```bash
  echo $PATH | tr ':' '\n' | grep "$HOME/bin"
  echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
  source ~/.bashrc
  ```
- 심볼릭 링크 확인:
  ```bash
  readlink ~/bin/llm   # agent.py가 있는 llm을 가리켜야 함
  ```

### `DEEPSEEK_API_KEY가 없습니다`

- 저장소 폴더의 `.env`, `/etc/env/.env`, 환경변수 중 하나에 키가 있는지 확인하세요. (`.env` 위치 예: `~/codespace/userscript/llm/.env`)

### 답변이 Markdown 원문으로 보임

- 파이프·리다이렉트(TTY 아님)거나 `LLM_RAW`가 설정된 경우입니다. 이때는
  로그·자동화에서 결과가 왜곡되지 않도록 원문을 그대로 출력합니다.
  ```bash
  echo "$LLM_RAW"; tty
  ```
- TTY인데도 `**굵게**` 같은 기호가 보이면 `NO_COLOR`가 설정돼 색 없이
  구조만 정리된 것입니다(기호는 지워집니다). `unset NO_COLOR` 로 색을 켭니다.

### 셸 실행이 거부됨

- TTY가 아닌 환경이면 `--yes`가 필요합니다.
- 기본(허용) 모드에서도 `sudo`·설치·폴더 밖 삭제는 확인을 받습니다.
  특히 권한 상승(`sudo` 등)은 목적 설명과 함께 **항상 다시** 묻고, 자동화에서
  생략하려면 `--yes`를 쓰세요(설치·삭제는 `a`로 한 번 허용해도 됩니다).
- 예상보다 자주 묻는다면 배너의 `확인=` 값을 보세요. `outside`로 떠 있으면
  `.env`의 `LLM_AUTO_WORKSPACE=1`이 원인일 수 있습니다(위 「설정과
  환경변수」). `llm --trust`로 이번 실행만 관대 모드로 돌릴 수 있습니다.
- 같은 폴더에서 반복 작업이 많으면 확인 프롬프트에서 `a`를 골라 그 폴더를
  기억시키거나, `llm shell allow`로 지금까지 허용된 범위를 확인하세요.
  `llm shell log`는 확인 없이(또는 `a`/`all` 덕분에) 실행된 명령까지 시간순으로
  보여 줍니다. 대화형(`llm`·`llm -i`·`llm repl`)도 기본이 **읽기 전용 자동**이라
  조회·테스트
  명령은 묻지 않고, 그 밖의 명령은 `a`(기억)나 `all`(이번만)로 넘기면 됩니다.
  `sudo`는 `all`로도 넘기지 못 하고 매번 확인합니다(`--yes`만 예외).

### 로컬 PC의 세션 관리

- 대화 기록은 현재 PC에서만 보관하며 기본 위치는 작업 폴더의 `.llm/history_<세션>.json`, 요약은 `.llm/summaries/`입니다.
- `llm session ls`로 세션 목록을 보고, `llm session view [이름]`으로 지난 대화를 확인할 수 있습니다. `session compact`는 로컬 요약을 생성합니다.
- `LLM_HISTORY=home`을 선택하면 기록은 `~/.local/share/llm/`에 저장합니다. 기본 위치를 변경하기 전에는 기존 기록을 백업하거나 수동 이전해야 합니다.
- `llm sync`는 대화 기록의 GitHub 유출을 방지하기 위해 사용하지 않습니다. `LLM_AUTO_SYNC=1`과 `LLM_AUTO_PULL=1`도 대화 기록 동기화를 활성화하지 못합니다.
- `git pull`은 **소스코드 업데이트용으로만 사용**합니다. 이 저장소의 이전 버전에서 Git이 추적하던 대화 파일은 GitHub `main`에서 제거됐으므로, 예전 PC에서 업데이트하기 전 로컬 `.llm/` 디렉터리를 별도 저장 공간에 복사하세요.
- 로컬 SSD 손상·PC 재설치에 대비한 별도 백업은 권장하지만 **다른 PC에서 세션을 이어가기 위한 Git 동기화는 제공하지 않습니다.**

## 개발 규칙

이 저장소에서 작업할 때 지켜야 할 규칙입니다.

1. **표준 라이브러리만** 사용합니다(의존성 추가 금지).
2. 변경은 **최소**로, 기존 구조와 UI 스타일(아이콘/색상/구분선)을 유지합니다.
3. 기존 파일 편집은 **먼저 `read`** 한 뒤 `edit`(replace), 새 파일은 `edit`(write)로 작성합니다.
   새 기능은 가능하면 `llmlib/`에 순수 함수로 두고 `agent.py`는 연결만 합니다.
4. **기능/CLI 옵션/동작이 바뀌면 `README.md`를 즉시 갱신합니다.**
5. 한글 응답을 기본으로 합니다.
6. `.env`, 키 파일 등 비밀 정보는 출력하지 않습니다.
7. 편집 후에는 `python3 -m py_compile agent.py llmlib/*.py`와 `python3 -m pytest -q tests`로 검증합니다.
8. **코드 수정 전 `git pull --rebase --autostash`, 검증 통과 후 커밋·`git push`**
   를 수행합니다. 검증 실패·중단 시에는 되돌리고 push하지 않습니다.
   **대화 기록은 로컬 전용**이며 자동·수동 Git 동기화가 차단됩니다. 절차 원본:
   [`.llm/rules.md`](.llm/rules.md).

세션 규칙 원본은 [`.llm/rules.md`](.llm/rules.md)에서 관리됩니다.
