# 대화 요약

## 사용자 목표/요청
- **셸 권한 설정 단순화**: CLI 옵션 4종+환경변수 2종, `SHELL_*` 테이블 43개의 중복을 `--ask LEVEL` 단일 옵션 + 등급 기반 단일 분류로 정리.
- **risky 모드에서도 y/N이 빈번한 원인 규명·개선**: 왜 자주 묻는지 실측 진단 후 개선.
- 최종 승인 결정: **① `.env`의 `LLM_AUTO_WORKSPACE` 끄기, ② 개선안 1+2+4 구현 승인, ③ (읽기전용 폴더 밖 허용)은 제외.**

## 결정된 사항과 이유
- **빈번한 확인의 진짜 원인**: 환경에 `LLM_AUTO_WORKSPACE`가 설정돼 있어 기본 `risky`가 아닌 **`outside` 모드로 동작** 중이었음. (저장 명령 32개 기준: risky 2/32=6%, outside 12/32=38%, all 30/32=94%)
- **남은 프롬프트는 대부분 오탐**: 따옴표 안 산문 경로(`echo "== /etc/x =="`), sed의 `/`를 경로로 오인, `$변수` 경로, 따옴표·정규식 안 `\|`를 진짜 파이프로 분리, heredoc 본문(`pip install` 단어)을 명령으로 스캔, `./` 스크립트 무조건 확인.
- **승인 재사용 한계 확인**: `all`은 그 턴만 유효(`auto_rest` 지역변수), `rm`/`mv`/`curl` 등은 `SHELL_NO_PREFIX_HEADS`라 정확 일치만 기억, 다중 조각은 조각마다 개별 y/N.
- **개선안 1+2+4 채택**(정책 변화 없이 오탐·반복 제거), 3(읽기전용 폴더 밖·loopback curl 허용)은 정책 변경이라 제외.
- 리팩터 안전장치로 **동등성 테스트(baseline)** 를 먼저 고정.

## 생성/수정된 파일과 핵심 코드 변경
- **`agent.py`**:
  - `import shlex` 추가, `shell_words()` 헬퍼 신설(인용부호 해석; 실패 시 `split()` 폴백).
  - `split_shell_commands()` 개편: 이스케이프(`\|`,`\;`)·인용부호 안 연산자 무시, `&` 추가, `chain_segments()` 래퍼 도입.
  - `SHELL_CHAIN_SPLIT` 제거 → `SHELL_META_PATTERN` 유지, 판정에서 `chain_segments()` 사용.
  - `scan_text()` 신설: heredoc 본문 제거 + 무해 리다이렉션 제거 후 보안 스캔.
  - `strip_heredoc_bodies()`에 `heredoc_marker()`(인용부호 존중) 도입, `SHELL_HEREDOC_EXEC_HEADS`(bash/sh/eval/sudo 등) 상수 추가 → `heredoc_shell_exec()`로 본문이 코드 실행되는 경우만 확인.
  - `needs_confirm_always()`를 `scan_text` 기반으로, `_deletes_outside_workspace()`를 `shell_words` 기반으로 변경.
  - `_workspace_path_ok(root, token, strict)` 추가: 공백 포함 산문·`$`/백틱 변수(비strict) 무시, `strict`(삭제·이동류)는 확인. `SHELL_PATH_STRICT_HEADS` 신설.
  - `_workspace_fragment_safe()`를 `shell_words`+`strip_env_assignments` 기반으로 재작성.
- **`ask_baseline.py`** (임시, 커밋 제외): 명령 87개 × 4모드 자동실행/확인 판정을 `ask_baseline.json`에 저장·비교. 결과: 차이 6건(모두 의도된 오탐 제거), risky 66→67, outside 45→49, all 25→26.
- **`ask_session.py`** (임시): 실제 세션 명령 47~50개로 리팩터 전후 비교. `risky 3→1`, `outside 15→12`, outside 프롬프트 조각 수 `174→118`.
