## 결정 사항과 이유
- todo UI는 TTY에선 제자리 갱신, 비TTY/`LLM_RAW`·화면 초과(`static`) 시 바뀐 줄만 새 줄 출력, 최종 답변 직전 `freeze()`로 블록 잔존 — pty 시뮬레이션·`LLM_RAW` 실행으로 정상 확인 후 커밋.
- 권한 단순화 설계안(제안, 미승인):
  - CLI `--ask {all,outside,risky,none}` 단일 옵션 + 환경변수 `LLM_ASK`; 기존 4옵션(`-y`→`none`, `--allow-all`→`risky`, `--auto-workspace`→`outside`, `--confirm-all`→`all`)은 **별칭으로 유지**(스크립트 호환).
  - 내부는 판정 함수 3개(≈182줄)·`SHELL_*` 상수 43개를 `classify(command, root) -> READ|LOCAL|RISKY|DENY` 하나로 통합, `SHELL_UNSAFE_PATTERN`·`WORKSPACE_BLOCK_*`·`ASK_*`를 **`SHELL_RISKY`에서 파생**(손 관리 제거), `SHELL_INTENT_*`도 같은 표에 설명 필드로 병합.
  - 이유: `sudo` 4표, `rm` 8표, `mv` 7표, `pytest` 3표 중복 → 명령 추가 시 4~8곳 수정 필요, 누락 = 보안 구멍.
  - 기본값은 **`risky` 권장**(현행 동작 유지, 되돌릴 수 없는 `rm ~/x`·설치·`sudo` 무확인 방지).
  - 검증은 **동등성 테스트**: 명령 80여 개에 대해 현행 3함수×4모드 판정을 JSON으로 저장 → 리팩터 후 모드별 "묻는지" 자동 비교.
- 세션 기록 실측(빈번한 확인 원인 진단): shell 명령 64개 중 프롬프트 대상이 `risky` 2/64(3%), `outside` 23/64(36%), `all` 58/64(91%) → `/etc/env/.env`에 **`LLM_AUTO_WORKSPACE`가 설정돼 있어 실제로 `outside` 모드로 동작**하는 것이 원인으로 추정.
