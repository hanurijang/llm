## 원인 분석 (재현 3건)
- **재현1**: 전부 `done`인 완료 계획도 `restore_todo`가 복원 → 옛 목표가 다음 실행의 목표처럼 표시.
- **재현2**: 완료된 계획 뒤 `goal` 없이 새 항목을 보내면 옛 goal이 그대로 유지됨.
- **재현3**: 도구 출력 등에 우연히 섞인 파싱 불가 스탬프 모양 문자열이 뒤에 있으면 `restore_todo`가 실패해 멀쩡한 계획을 잃음.
- 히스토리 확인: index 0에 `.env` goal 스탬프, tool 메시지(104)에 `{json.dumps(state)}` 리터럴 스탬프 존재.

## 결정 사항과 이유
- **완료된 계획은 복원·이어가기 대상이 아님** (`todo_active()`: 미완료 항목 있으면 활성, 전부 done이면 비활성).
- 파싱 가능한 **마지막** 스탬프만 채택, 파싱 실패 스탬프는 건너뜀.
- 스냅샷을 저장 시마다 최신화하고, 계획이 끝나면 요약 헤드에서 **계획 블록·스탬프를 제거**해 모델이 옛 목표를 못 보게 함.

## 생성/수정된 파일과 핵심 변경
- **`agent.py`**
  - `restore_todo`: 파싱 가능한 스탬프만 사용, **전부 done이면 복원 안 함**.
  - `tool_todo`: 이전 계획이 없거나 전부 완료면 `goal` 생략 시 **옛 목표 물려주지 않음**(`CURRENT_TODO_GOAL=""`).
  - `todo_active()` 신설, `todo_plan_text()`/`todo_stamp()`가 이를 사용(계획 없으면 `""`).
  - `refresh_todo_snapshot()` 신설, `save_history`에서 호출: 요약 헤드의 계획/스탬프를 최신으로 교체, 끝난 계획이면 제거. 계획을 모르는 프로세스(`--view`)는 헤드 미변경.
  - 상수 `TODO_PLAN_HEADER` 추가, `py_compile` 통과.
- **`.llm/rules.md`**, **`README.md`**: 이전 턴에서 autopull 안전장치·`.env` 우선순위 반영 완료(이번 todo 수정은 코드만).
