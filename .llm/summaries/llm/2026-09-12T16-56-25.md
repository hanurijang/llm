## 사용자 목표/요청
- DeepSeek API 키를 한 곳에서 관리: `.service`(systemd)와 `/etc/env/.env` 혼동 해소, **저장소 폴더 `.env`로 통일** 요청
- `git push` 여부 확인 → 이후 **세션 폴더를 push하면 대화 내용도 업로드되는지** 질문
- "대화 내용도 세션 폴더에 저장하기로 했던 것 아니냐" → **다른 PC에서 대화를 이어가고 싶다**는 의도 확정
- `fastapi.service`가 아니라 각 폴더 `.env`를 쓰는 게 맞는지 확인
- 마지막: **다른 PC에서 대화 시 자동 pull되어 이어지는지** 질문(대화 종료로 미답변)

## 결정 사항과 이유
- **`.env` 조회 순서 확정**: `LLM_ENV_FILE` → 저장소 `.env`(우선) → `/etc/env/.env`(폴백). 이미 설정된 환경변수는 유지.
- `.gitignore`에 `.env`가 있어 **커밋/push 안 됨** → 키 유출 방지.
- `systemd`의 `CLIENT_API_KEYS`는 raspApi 클라이언트 인증용으로 **DeepSeek 키와 무관**함을 전수 검색으로 확정.
- **`fastapi.service`는 수정 불필요**: `EnvironmentFile` 없음, `raspApi`가 자체 `appenv`로 `raspApi/.env`를 읽음(`SLIDES_LLM_API_KEY` → `DEEPSEEK_API_KEY` 순). `/etc/env/.env`는 현재 **존재하지 않음**(정리됨).
- 대화 기록 저장은 **이미 다른 세션에서 구현·push되어 있었음**(`354ebe5` 등) → 중복 편집은 `pull --rebase`로 대체되어 커밋 없음.
