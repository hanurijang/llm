## 사용자 목표/요청
- 이전 대화에서 미해결로 남은 **stream 모드 최종 응답 미출력 문제** 수정 ("좋아 수정해봐")

## 조사 및 결정 사항
- **재현 실패**: CLI(`--no-stream` vs stream) 및 다단계 도구 호출 루프 테스트 모두 정상 → 최종 답변 미출력 문제는 현재 경로에서 재현 안 됨
- API 원시 응답에 `reasoning_content`(thinking) 필드와 `usage.completion_tokens_details.reasoning_tokens` 존재 → **thinking 모드가 기본**
- 코드/README에 `reasoning|thinking|max_tokens` 참조 전무 → thinking 출력이 파싱·표시되지 않는 상태
- 문서상 tools 사용 시 `reasoning_content`를 되돌려주지 않으면 400 오류라는 단서 확인했으나, 실제 테스트(A: 미포함 / B: 포함) 모두 `finish=stop`으로 오류 미발생
- **핵심 원인 후보 확정**: `stream_chat`이 스트림 중 I/O 예외(`TimeoutError`, `IncompleteRead`, `ConnectionResetError` 등)를 잡지 않아, thinking으로 첫 토큰이 늦거나 연결이 끊기면 트레이스백으로 죽고 최종 답변이 출력되지 않음 → 예외 처리 + thinking 처리 보완으로 결정

## 생성/수정된 파일 (`agent.py`)
- **임포트 추가**: `http.client`, `typing.Callable`
- **`strip_reasoning()` 신규**: 저장 시 `reasoning_content` 제거
- **`save_history()` 수정**: `strip_reasoning()`을 거쳐 저장
- **`StreamInterrupted` 예외 클래스 신규**: 부분 응답(`partial`)·`finish` 보존
- **`stream_chat()` 재작성**:
  - 반환값 4개로 확장 (content, tool_calls, finish_reason, **reasoning_content**)
  - `reasoning_content` 델타 수집, `on_delta` 콜백으로 content/reasoning 이벤트 방출
  - I/O 예외를 `StreamInterrupted`로 변환(부분 내용 보존)
- **`complete()` 수정**:
  - `thinking: bool = True`, `on_delta` 파라미터 추가 → 반환값 4개
  - `thinking=False` 시 `payload["thinking"] = {"type": "disabled"}`
  - `StreamInterrupted` + 부분 내용 있으면 부분 사용, 없으면 비스트리밍 재시도
